`close.rs:561–607` (`judge`): якщо `scope::plan_branch` каже, що гілка

- слаг називає хвилю дерева, і та **не скасована** → `report_text(root,

«історії нема», і лише тоді диск.

## Блокер кола шостого: два стани звіту

**Твердження автора.** `security.resistance` і
`reliability.fault-tolerance` переписані: найдешевший обхід — один
непробільний символ; «нема» і «порожній» сказані нарізно; на обох
стоїть проба.

**Мій замір.** Три стани, три окремі пісочниці, бінарник цього дерева:

```
0 байтів      exit 1   «у плану хвилі 0019-a-full-wave файл звіту є, і він порожній»
9 байтів "   \n\t\n  \n"  exit 1   той самий рядок
1 байт  "x"   exit 0   «блокерів нема»
```

Обидві відповіді тепер правдиві дослівно. `security.resistance` каже
«найдешевший обхід — ОДИН непробільний символ» — зміряно, так і є.
`reliability.fault-tolerance` каже «файл є і порожній — ТЕЖ червоне,
окремим рядком, який каже саме це» — зміряно, рядок інший і каже саме це.

**Мутант, що міняє два стани місцями (M2).**

```rust
None => Some("close-lack-plan-review-empty"),
Some(text) if text.trim().is_empty() => Some("close-lack-plan-review"),
```

Умирає на `tool/tests/the_plan_has_a_reader_test.rs:133` — assert
«a plan with NO report is told the report is missing, not that it is
empty». Числа під мутантом лишаються правильні (exit 1 в обох станах),
вмирає саме розрізнення слів. Пастка кола шостого закрита.

**Мутант, що приймає порожній файл (M8)** — рядок `Some(text) if
text.trim().is_empty() => …` вилучено: умирає на `:184`.

## Блокер-сусід кола шостого: пастка без виходу на скасованій хвилі

**Твердження автора.** На скасованій хвилі заслін мовчить; проба це
тримає; мутант, що знімає умову, вмирає.

**Жива пісочниця.** План-гілка, у шапку хвилі дописано
`cancelled: "передумали"`, закоммічено:

```
keel close   exit 0     заслін не сказав жодного слова
keel check   exit 0
keel review  exit 0     «хвилю 0019-a-full-wave скасовано — передумали
                         (§6.3-а): пакет не збирається, судити нічого»
keel next              веде на `keel review` (див. знахідку 6)
```

Виходу з кола більше нема, бо кола нема: `close` зелений, гілку можна
злити. До хвилі (бінарник `origin/main`) той самий стан теж давав
exit 0 — тобто регресії немає, а пастку створювало саме перше різання
цієї хвилі.

**Мутант, що знімає умову «жива хвиля» (M1).**

```rust
let live = scan.waves.iter().any(|wave| &wave.slug == slug);
```

Умирає на `:217` — `assert_eq!(code, 0, "a cancelled wave's plan branch
closes…")`. Тобто пастку тримає проба, а не пам'ять.

## Три розрізи, які заперечували власний замір

### `performance.capacity` — обсяг читаного РОСТЕ

Зміряно накладкою на `git` (шим у PATH, що логує argv і робить
`exec /usr/bin/git`), плюс прямим заміром байтів:

```
звіт плану 1 053 020 байтів
викликів `show HEAD:` за одне `keel close` — рівно 1
git show HEAD:./keel/reviews/0019-a-full-wave-plan.md | wc -c → 1 053 020
```

Файл іде через суд **цілком**. Приріст сталий (один файл на закриття) і
від розміру дерева не залежить. Відповідь правдива.

### `safety.operational-constraints` — час ДОДАЄТЬСЯ

Спершу я зміряв те, що міряється точно, — **процеси**. Порівняння
дерева з M0 (заслін вилучено цілком), лічба через шим:

| | усього git | `branch --show-current` | `show HEAD:` | `rev-parse --verify` |
|---|---|---|---|---|
| M0, звіт є | 30 | 10 | 0 | 1 |
| дерево, звіт є | **32** | 11 | 1 | 1 |
| M0, звіту нема | 30 | 10 | 0 | 1 |
| дерево, звіту нема | **33** | 11 | 1 | 2 |

**+2 процеси на зеленому шляху, +3 на червоному** — дослівно ті самі
три виклики, що названі в `performance.time-behaviour`. Цю відповідь
підтверджено до цифри.

Час (30 повторів кожного виклику після прогріву, ця сама машина):

```
перший прогін:  branch --show-current 18.2 мс | show HEAD 17.3 / 16.0 мс | rev-parse 13.8 мс
                → +35 мс зелений шлях, +48 мс червоний
другий прогін:  branch --show-current 24.7 мс | show HEAD 26.9 / 27.0 мс | rev-parse 25.0 мс
                → +52 мс зелений шлях, +77 мс червоний
```

Напрямок і порядок величини підтверджено: час **додається**, десятки
мілісекунд на кожне закриття план-гілки. Числа картки (+26 / +40) я не
відтворив; два мої прогони на тій самій машині розійшлися між собою
вдвічі. Це не неправда — це не відтворюване (див. знахідку 5).

### `maintainability.modifiability` — хвиля МІНЯЄ, як додають нові суди

`git diff origin/main`:

- було: семичленний ланцюг `&&` у підвалі **і** окремий вираз суми в
  `Ok((report, blockers + verify_blockers + …))` — два місця;
- стало: `let held = … + usize::from(plan_lacks.is_some());` — одне,
  вживане підвалом (`held == 0 && …`) і кодом виходу (`Ok((report,
  held, …))`).

**Мутант M5** (повернуто рукописний ланцюг у підвалі, суму лишено лише
коду виходу) умирає на `:121` — assert «the footer does not deny what
the exit code carries». Тобто саме заміна ланцюга сумою тепер тримається
пробою.

Жива перевірка суперечності підвалу з кодом виходу — чотири стани:

```
план-гілка, звіт є                                exit 0, «блокерів нема»
план-гілка, звіту нема                            exit 1, «блокерів нема» НЕ сказано
план-гілка, звіт є + один розріз без відповіді    exit 1, «знахідок суду документів … 1»
план-гілка, звіту нема + розріз без відповіді     exit 1, обидва рядки, підвал мовчить
```

Жодного «блокерів нема» над виходом 1 не знайдено.

## Знахідки

### 1. Мутант, що читає диск замість історії, переживає всю батарею — СЕРЕДНЯ, **не блокує**

`close.rs:591` замінено на `std::fs::read_to_string(…)`: 240 passed,
1 failed (той самий `outside_word_test`) — тобто батарея не змінилась.

Чому це важить. Рядок, який суд друкує, каже дослівно: «keel/reviews/
<хвиля>-plan.md **нема в історії цієї гілки**». `security.resistance`
каже: «машина тримає ФОРМУ — що файл **є в історії гілки** і що він не
порожній». Другу половину тримає проба (M8 умирає). Першу — не тримає
ніщо на цьому місці виклику. Над звітом РОБОТИ ця сама властивість
тримається окремою пробою `tool/tests/report_commit_test.rs`; над звітом
ПЛАНУ такої проби нема.

Жива вада відсутня: я побудував стан «файл на диску, не закоммічений» —
`close` дає exit 1, як і має. Це дірка проби, не дірка суду, і тому не
блокує. Ліки — одна пісочниця на сім рядків усередині вже наявної проби
(записати `-plan.md` і **не** коммітити).

Це сьоме коло поспіль, у якому мутант над цією хвилею переживає батарею;
попередні шість щоразу знаходили іншу властивість. Ця — остання з
названих у самих рішеннях.

### 2. Клауза контракту каже, що машина вимагає того, чого вона не вимагає — СЕРЕДНЯ, **не блокує**

`keel/contracts/tool-close.md`:

> на гілці `plan/<хвиля>`, **де в дереві є хвиля з таким іменем**,
> `close` вимагає `keel/reviews/<хвиля>-plan.md` в історії гілки

Зміряно: скасована хвиля — це хвиля з таким іменем у дереві, і `close`
там **нічого не вимагає** (exit 0, жодного слова). Слова «скасован» у
`tool-close.md` нема взагалі; у `tool-review.md` аналогічний виняток
названо прямо (рядок 58).

Те саме в нормі: §9.9 в усіх трьох файлах каже «його вимагає той самий
суд на гілці `plan/<хвиля>`» — без застереження. І другий новий блокер
клаузи (`plan/<слаг>`, якого в дереві нема) в §9.9 не названо зовсім,
лише в контракті.

Не блокує, бо §6.3-а вже каже загальним правилом «скасована хвиля поза
судом — ані її обіцянки, ані її scope не судяться», і код узгоджений із
цим правилом. Але контракт тут-таки вміє називати свої межі дослівно
(«Легка хвиля … звіту не потребує», «Де історії нема … це названа межа,
а не виняток») — і саме на цьому місці не назвав. Ціна правки — півречення.

Окремо зважив: `interaction.self-descriptiveness` цієї хвилі ставить
власний стандарт — «машина не сміє вимагати того, чого норма не
називає». Дзеркало того ж правила — «норма не сміє казати, що машина
вимагає того, чого вона не вимагає» — тут порушено, але покрито §6.3-а.

### 3. `maintainability.testability` каже «на п'яти станах», а їх шість — НИЗЬКА, не блокує

У пробі `the_plan_has_a_reader_test.rs` план-гілкових станів `close`
шість: `planbare` (101), `planread` (140), `planwrongname` (159),
`planempty` (179), `plancancelled` (204), `plannowave` (292). Шостий
(`plancancelled`) додано саме цим колом; число в рішенні лишилось
старе. Відповідь, якої не тримає власний замір, — дрібна, але це та сама
форма, що її ловили кола третє–шосте.

### 5. Мілісекунди в `safety.operational-constraints` не відтворюються — НИЗЬКА, не блокує

Картка називає 12.5 / 13.9 / 13.1 мс і підсумки +26 / +40. Два мої

Зміряно: у `close-plan-no-wave` (обидві мови) слова «натомість» нема

відмовляє.)

### 7. Файл у scope, чия причина живе лише в повідомленні коміту — НИЗЬКА, не блокує

`tool/tests/verdict_limits_test.rs` стоїть у `files:` хвилі. Правка —
`&whole_said[..min(600)]` → `whole_said.chars().take(600)`. Коміт `d04389f`
називає причину чесно: «One thing fixed in passing, not this wave's
subject: `verdict_limits_test` sliced a report at byte 600 and panicked
inside 'я'». Картка про це не каже нічого — а картка переживає merge,
повідомлення коміту читають рідше.

Додатково: зміна **неспостережна**, доки проба зелена — аргументи
`assert!` обчислюються лише коли assert падає. Тобто в scope стоїть
правка, якої не тримає і не може тримати жодна проба батареї. Це
законно (§4.4 вимагає оголосити те, чого торкнувся), але заслуговує
рядка в картці.

### 8. `maintainability.modularity` каже «там само», а це різні функції — НИЗЬКА, не блокує

Суд над звітом плану — `judge` (`close.rs:561`), власний лічильник
`plan_lacks`, власний рядок звіту. Суд над звітом роботи — `wave_state`
(`close.rs:1557`), списком `lacks` усередині стану хвилі. Спільна в них
рука `report_text` і файл. «Живе там само» правдиве на рівні модуля і
неправдиве на рівні функції; `maintainability.reusability` («одна рука з
параметром») сказано точніше й правдиво.

Дрібний слід того ж: порожність перевіряється двома різними написаннями —
`text.trim().is_empty()` (план) і `text.split_whitespace().next().is_none()`
(робота). Результат однаковий, але це третя копія однієї думки.

## Чотири питання §9.9

**Про що ми змовчали?**

Про виняток для скасованої хвилі — у контракті й у нормі (знахідка 2);
код і проба про нього кажуть, документи ні. Про те, що властивість «в
історії гілки», яку заслін називає вголос, на цьому місці виклику не
тримається нічим (знахідка 1). Про правку `verdict_limits_test.rs` —
у картці (знахідка 7). Все інше, що я шукав, названо: борг ланцюга `&&`
у BACKLOG і в тілі картки, радіус звуження, два ризики, межа §7.8.
Ця хвиля мовчить помітно менше за попередні свої кола.

**Чи всі можливі сценарії враховані?**

Станів план-гілки, які я вигадав і побудував, — десять; проба тримає
шість. Непокриті: звіт на диску без коміту (знахідка 1), вкладена гілка
`plan/<слаг>/extra` (зміряно: слаг стає `<слаг>/extra`, хвилі такої
нема, суд каже `close-plan-no-wave` — поводиться правильно), і
план-гілка хвилі, яка вже закрита (заслін вимагає звіт плану — розумно,
шкоди не видно). Один сценарій, якого не враховано **навмисно** і про
який сказано в BACKLOG: слаг, що кінчається на `-plan`, зіткне звіт
роботи однієї хвилі із заслоном плану сусідньої. Я перевірив форму:
`format!("{slug}-plan")` справді дасть зіткнення, і жоден суд імен хвиль
такого слага не забороняє. Ризик малий, названий, у scope не взятий.

**Чи реалізовано все обіцяне, без тихого звуження?**

Реалізовано **більше**, ніж обіцяв якір: додано другий блокер
(`plan/<слаг, якого нема>`), якого в плані на якорі не було. Він
названий у контракті, тримається пробою і мутантом M11 — тобто це
розширення вголос, а не тихе. Тихого звуження не знайшов: обидві
половини issue #53 на місці (заслін і порядок поради), і англійська
половина зміряна проти `origin/main`, а не взята на віру.

**Чи покриває тест увесь сценарій, а не його кут?**

Майже. Проба ходить шістьма станами план-гілки, обома мовами, і
перевіряє слова пакета — те, чого бракувало на четвертому колі.
Дванадцять із тринадцяти мутантів вона вбиває. Кут, якого проба не
дістає, один і названий: **історія проти диска** (знахідка 1). Плюс
рішення `maintainability.testability` рахує стани неправильно
(знахідка 3) — тобто картка описує пробу, якої вже нема, хоч проба
ширша, а не вужча.
