## Знахідки

- **R-1 (важка).** Абзац правила питав **відповідь конфігу**, а не
  те, що стоїть. Зміряно два живі випадки: `keel init` у не-git теці
  друкує «red commit-msg — git refuses» і через девʼять рядків пише
  агентові, що hook тримає правило; і **свіжий клон** — git hook-ів
  не клонує, тож кожен колега читає гарантію машини, якої в його
  клоні нема, а `keel check` про це мовчить.
- **R-2 (важка).** `install.sh` **зламано на другому запуску** —
  тому самому, який шапка скрипта і README звуть оновленням.
  `git checkout -` під `set -e` у клоні, який ніколи не рухали. На
  базі той самий сценарій — exit 0. Регресія цієї ж хвилі.
- **R-3 (важка).** «Рука», яку називає `version`, для справжнього
  формату піна не працює: поле тримає `0.1.0`, теґи — `v0.8.x`, і
  жоден опублікований теґ не збереться. Проба цього не ловила — вона
  брала вигаданий пін і перевіряла лише форму рядка.
- **R-4 (важка).** Згенерований CI **не читає піна** — завжди ставить
  `main`, тож пінований проєкт дістає ту саму червону CI, просто на
  два рядки нижче. А коментар кроку радить поставити `KEEL_REF` в
  інсталяторі, який сьогодні за тим URL цього слова не знає.
- **R-5 (важка).** Ядро `the-pin-has-a-hand` не тримав ніякий суд:
  проба читала `install.sh` **як текст**. Дві мутації — «ніколи не
  читати KEEL_REF» і «вичитувати origin/HEAD замість названого ref»
  — пережили **повну** батарею. Тобто «мовчазний білд main», рівно
  той баг, задля якого сценарій написано, повернувся зеленим.
- **R-6 (важка).** Половина `the-block-names-what-holds-it` про
  `keel check` **ніколи не була червоною**: пісочниця не мала хвиль,
  тож судимий рядок там не друкувався взагалі. Мутація, що повертала
  внутрішню нотатку keel-а, пройшла повну батарею.
- **R-7** (сер.). Абзац no-hook тримався одним негативним grep-ом:
  мутація, де абзац **обіцяє pre-commit hook** і водночас заперечує
  суд, — зелена. А «названо, що досі судить» задовольнялось
  загальним списком лупа шістнадцятьма рядками вище.
- **R-8** (сер.). `keel/contracts/tool-generated.md` названий у
  трансформі й **не чіпнутий**; описує блок як функцію самого
  `mode` і мовчить про крок постановки.
- **R-9** (сер.). Рішення `security.integrity` і
  `compatibility.co-existence` неправдиві: cargo кладе **73 МБ** у
  `CARGO_HOME`, поза обома названими теками.
- **R-10** (сер.). «Проєкт, що вже має власний крок, другого не
  дістає» — не реалізовано перевіркою; хто послухався файлу, дістає
  докір на **кожному** `keel update` довічно.
- **R-11** (легка). Поєднань не чотири, а шість (три режими × дві
  ручки); два не проби́.
- **R-12** (легка, успадкована). Кореневий `METHODOLOGY.md` не
  судить ніхто: відкат §4.13 **лише там** пройшов батарею.
- **R-13** (легка). `install.sh`, який тягне CI, сам береться з
  рухомої `main` — без піна і без перевірки.

## Чотири питання — відповіді рецензента

1. **Про що змовчали?** Що `rule_for()` питає відповідь, а не диск;
   що CI не тримає сценарію в пінованому проєкті; що `install.sh`
   зламався на звичайному оновленні (журнал каже «зміряно наскрізь»,
   а зміряно лише дорогу `KEEL_REF=<sha>`); про 73 МБ у `~/.cargo`;
   про контракт, названий і недоторканий.
2. **Чи всі сценарії враховані?** Ні: рядок про `keel check` не мав
   суду взагалі; «команда справді працює» не працює для формату
   піна, який приймає конфіг; «тоді»-клауза про власний крок не
   реалізована.
3. **Чи є тихе звуження?** Три: сценарій каже «де hook поставлено» —
   код читає відповідь; `safety.safe-integration` знижує «тоді» до
   «межа сказана словами»; `reliability.faultlessness` каже «чотири
   поєднання», коли їх шість.
4. **Чи покриває тест сценарій, а не кут?** Кут. Усі три проби
   судили **текст артефакту підрядками**, а не поведінку.

## Диспетчеризація автора

**Усі тринадцять зроблено**, трьома коммітами.

**R-2 — першою, бо жива.** Причина точна: `checkout -` потребує
`@{-1}`, якого в клоні, що ніколи не рухали, нема. Тепер скрипт
вертається з приколотого стану **головою віддаленого репозиторію** і
лише тоді, коли HEAD справді відірваний. Зміряно чотири дороги:
свіжа, друга, пінована, і назад із пінованої — усі exit 0.

**R-1 — і відповідь на нього не та, якої просив рецензент.** Абзац
**не повинен** читати диск, і це важливіша половина: артефакти
судяться відбитком на кожній машині, а git hook-ів не клонує — тож
текст, що мінявся б із наявністю hook-а, читався б як правлений
рукою на кожному раннері і в кожному чужому клоні. Абзац каже, що
проєкт **відповів**. Чи стоїть hook **тут** — питання про цю машину,
і його ставить `keel check` рядком меж (не знахідкою: на раннері
комітів судити нема чого). Зміряно на справжньому клоні — git лишив
hook позаду, рядок зʼявився.

**R-5, R-6, R-7 — усі три про суд, який тримав ніщо.** Проба піна
тепер **жене справжній install.sh** проти справжнього git-репозиторію
(стаб `cargo` на PATH, щоб не платити збіркою; підробка названа в
шапці файлу). Пісочниця «чужого проєкту» несе закриту хвилю, тож
судимий рядок нарешті друкується. Абзац no-hook судиться **сам по
собі**, а не в тексті блока навколо, і позитивно, і негативно.

**Контрфакти зміряні, не прочитані.** Кожна мутація, яку рецензент
назвав вижилою, тепер червонить: M10 (не читати `KEEL_REF`), M14
(`origin/HEAD` замість названого ref), M-R2 (старий `checkout -`),
M16 (абзац обіцяє pre-commit hook), M2 (абзац не називає, що судить),
M12 (нотатка про чергу keel-а повертається), M13c (відкат §4.13 у
кореневому файлі), і вимкнення самого рядка про відсутній hook.

Решта: пін їде в CI-крок (`KEEL_REF` із конфігу, перед судами);
`version` каже межу «git ref за іменем, а не число з keel.toml»;
`CARGO_HOME` названий у шапці скрипта, у коментарі кроку, в README і
в рішенні; файл несе повний рецепт, як лишити свою редакцію без
вічного докору; шість поєднань замість чотирьох; кореневий
`METHODOLOGY.md` дістав суд; контракт `tool-generated` описує те,
чим модуль став.

Батарея після: **136 зелених** (було 135), 0 падінь; `clippy -D
warnings` і `fmt --check` чисті; `keel check .` — 62 документи, 0
знахідок.

## Що лишилось поза хвилею

- **Щабель дистрибуції** (`~/.keel/versions/`, launcher, перевірений
  checksum) — свідомо не закритий; межа названа в скрипті, у
  `keel version`, у README і в черзі.
- **Жоден опублікований теґ не несе теперішньої розкладки** — доки
  не буде теґу v2, `KEEL_REF` бере лише коміт або гілку.
- **`install.sh`, який тягне CI, сам неприколотий** — рядок черги
  (R-13).
- **Справжній прогін на GitHub Actions** — раннера тут нема; усе
  зміряно текстом файлу і локальним бігом тих самих команд.
