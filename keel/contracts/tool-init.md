Рука рами (NEW-CONCEPT «Наскрізні», §8.7): `keel init` ставить
проєктові раму методики одним рухом — і ніколи нічого не топче.

- Народжує теки keel/waves/, keel/contracts/, keel/reviews/ (кожна
  з .gitkeep, щоб порожня тека пережила git) і keel.toml зі
  закоментованим словником конфіга (NEW-CONCEPT, Config: version —
  порадою стоїть бігуча версія бінарника, — lang, adapter, mode) —
  свідомо нічого не вмикаючи: типові значення лишаються словам
  config. Наявній теці без .gitkeep файл
  догодовується окремим словом — новий порожній файл не топче
  нічого, а «доносить те, чого бракує» лишається правдою. Ставить
  commit-msg hook рукою gate (§9.3).
- Кожен шмат рами — свій рядок звіту: «народжено» або «вже стоїть»
  (повторний біг нічого не міняє байт-у-байт), а шмат, що не став,
  — рядок відмови вголос з причиною і «натомість» (git мовчить —
  hook не ставиться, чужий hook — не перезаписується). Другим
  числом run віддає рахунок шматів, що не стали: нуль — вихід
  зелений, інакше червоний.
- Наявний keel.toml — чий завгодно — не чіпається, і для рішень
  рами його зміст не судиться: «вже стоїть» кажеться про факт
  файлу (зміст судить config школою §7.9). Мова виводу — наскрізна
  школа config, як у кожної команди; битий keel.toml не править
  виклик мовчки: відмова config кажеться вголос рядком, і рама все
  одно доноситься типовою мовою.
- Рядок правил ignore (з хвилі 0020 — третій подарунок першого
  поля): рама читає `.gitignore` кореня і питає конфіг про адаптер,
  тоді каже одне з чотирьох — файлу нема (порада завести його з
  іменем теки збірки адаптера), файл є без правила (порада дописати
  рівно цей рядок), правило стоїть, або адаптера нема кому назвати
  теку. Рама **радить, а не пише**: `.gitignore` — файл проєкту, не
  рама методики, і жодного його байта init не чіпає. Рада ніколи не
  червонить раму — рахунок шматів, що не стали, від неї не росте.
- Хвіст звіту — нагадування §8.7 (вимкнути squash і rebase в
  налаштуваннях репозиторію: правило тримає вимкнена кнопка) і
  «далі — keel plan <перша хвиля>».
- Четвертий модуль, що пише (після trust, hook і plan); пише лише
  під keel/, keel.toml у корені і hook туди, куди покаже git.
