Адаптер javascript (хвиля 0046): єдине місце, що знає, як node-проєкт
тримає свої тести і свої модулі. Кличе `node --test` командою системи
— так само, як людина в терміналі, — і **не пише в проєкт нічого**
(зміряно порожнім `find` після `close`). TypeScript — не окрема мова
для цього бігуна: node 22 знімає типи сам, тож `.test.ts` судиться цією
ж рукою. Імена адаптера: `javascript`, `typescript`, `node`, `js`, `ts`.

**`node --test`, і це сказано вголос:** jest, vitest, mocha — інші
бігуни, інші хвилі.

## Мова, що НЕ розрізняє станів кодом виходу

| стан | код | TAP |
|---|---|---|
| зелене | 0 | `ok N - <імʼя>` |
| тест упав | **1** | `not ok N - <імʼя>` + діагностика |
| SyntaxError у модулі | **1** | `# SyntaxError: …`, потім `not ok 1 - <файл>` |
| імʼя без збігу | **0** | `ok 1 - <файл>` — **файл порахований за пройдений тест** |
| нема тестів | 0 | `# tests 0` |
| `skip` / `todo` | 0 | `ok N - x # SKIP`, `not ok N - y # TODO`, `# fail 0` |

Це перша мова, чий бігун не розрізняє станів кодом — і гірша за
ruby: там «не бігло» хоч не зелене, а тут node виходить із 0 і рахує
сам файл за пройдений тест. Тож **код не питається ніколи**. `classify`
бере рядок TAP, що називає **саме цей** тест: `ok` — зелене, `not ok`
— червоне, `# SKIP`/`# TODO` — не бігло. Жодного рядка з іменем: якщо
node надрукував `# …Error: …` і `not ok` для самого файлу — злам
завантаження, відмова **зі словами node** (`SyntaxError: Unexpected
token 'true' (file:///…/src/toy.js:1)`); інакше — «не бігло» (§7.12).

- `test_files`: `test/**` і `tests/**`, імена `*.test.{js,mjs,cjs,ts,mts}`.
  node збирає ширше — `*-test.*`, `*_test.*`, `test-*.*`, будь-що під
  `test/` — і ця межа названа в `keel check`.
- `unread_files`: решта сирців у `test/`/`tests/` — помічники,
  фікстури — названі поіменно.
- `module_paths`: `toy.bar` → `src/toy/bar.{ts,js,mjs,cjs,mts}`,
  `src/toy/bar/index.{ts,js}`, і те саме в корені: типізований перед
  простим, файл перед `index`. Крапки роблять теки, як у python; слеш у
  сегменті суд форми відкидає як «поза проєктом», порожній сегмент —
  не модуль.
- `run_test` жене `node --test --test-reporter=tap
  --test-name-pattern='^<імʼя>$' <файл>`. **Імʼя йде в регулярний
  вираз, тож екранується** (`escape_regex`): `a.b (x)` → `^a\.b \(x\)$`.
  Без цього `a.b` збігалось би з `axb`, а `(` ламала б бігун — урок
  хвилі 0044 про рядок, відданий чужій програмі. Імʼя іде окремим
  аргументом, не крізь шел.
- `run_all` жене **по одному файлу** (TAP називає тест, а не файл) і
  бере з TAP і перелік, і вироки: `tap()` читає `ok`/`not ok N - імʼя`
  з YAML-блоком під ним (`---` … `type: 'test'|'suite'` … `...`).
  Рядок самого `describe` — `type: 'suite'`, у мапу не йде; `# SKIP`/
  `# TODO` — не бігло, у мапі нема; рядок для самого файлу — не тест.
  Ключ — `adapter::battery_key`.

## Дві речі, які мова робить інакше

**Перша: імʼя тесту — голе, і всередині `describe` теж.** TAP друкує
`ok 1 - inside`, а `--test-name-pattern='^inside$'` вибирає саме його
— `describe` не додає префікса, на відміну від ExUnit. Тож читач тегів
не стежить за блоками. Наслідок, названий вголос: два тести з одним
іменем у різних `describe` не розрізнити — ні тегом, ні бігуном.

**Друга: читач коментарів — четвертий, і не член родини `#`.** JS має
`//` і `/* */` як rust, але `'…'` тут рядок (у rust — час життя), а
шаблонний рядок у зворотних лапках біжить через кілька рядків. Малий
власний читач (`strip_js`): `//`, `/* */` (не вкладені), три види
лапок з екранами; звичайний рядок не переходить рядка (де здається, що
переходить, — це апостроф у регулярці, і рядок — код). Один на js і
ts, бо це та сама робота. Межа: літерал регулярного виразу `/…/` не
читається — лапка в ньому може зʼїсти решту рядка.

## Межі, названі вголос

- читається `test/` і `tests/` з одним іменем файлу; node збирає ширше;
- однакові імена в різних `describe` не розрізнити;
- jest/vitest/mocha не читаються;
- `/…/`-літерали в суді форми не читаються.
