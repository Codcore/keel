Адаптер javascript (хвиля 0046): єдине місце, що знає, як node-проєкт
тримає свої тести і свої модулі. Кличе `node --test` командою системи
— так само, як людина в терміналі, — і **не пише в проєкт нічого**
(зміряно порожнім `find` після `close`, і з `NODE_COMPILE_CACHE`, що
показує в проєкт, теж: цю змінну адаптер знімає зі середовища, бо з
нею node лишав `.ncc/` — рецензія 0046 R-6; і `NODE_OPTIONS` — хвиля
0050: `--test-skip-pattern` у ній виймав червоний тест із батареї,
глобальне ревʼю 2026-09-06, баги R-6). TypeScript — не окрема мова
для цього бігуна: node 22 знімає типи сам, тож `.test.ts` судиться цією
ж рукою. Імена адаптера: `javascript`, `typescript`, `node`, `js`, `ts`.

**`node --test`, і це сказано вголос:** jest, vitest, mocha — інші
бігуни, інші хвилі.

## Мова, що НЕ розрізняє станів кодом виходу

| стан | код | TAP |
|---|---|---|
| зелене | 0 | `ok N - <імʼя>` |
| тест упав | **1** | `not ok N - <імʼя>` + діагностика |
| SyntaxError у модулі | **1** | `# SyntaxError: …`, потім `not ok 1 - <файл>` |
| імʼя без збігу | **0** | `ok 1 - <файл>` — **файл порахований за пройдений тест** |
| нема тестів | 0 | `# tests 0` |
| `skip` / `todo` | 0 | `ok N - x # SKIP`, `not ok N - y # TODO`, `# fail 0` |

Це перша мова, чий бігун не розрізняє станів кодом — і гірша за
ruby: там «не бігло» хоч не зелене, а тут node виходить із 0 і рахує
сам файл за пройдений тест. Тож **код не питається ніколи**. `classify`
бере **всі** рядки TAP, що називають **саме цей** тест (бо імʼя не
унікальне — див. нижче): є `not ok` серед них — червоне; інакше є `ok`
— зелене; лише `# SKIP`/`# TODO` — не бігло. Жодного рядка з іменем:
якщо node надрукував `# …Error: …` і `not ok` для самого файлу — злам
завантаження, відмова **зі словами node і місцем** (`SyntaxError:
Unexpected token 'true' (file:///…/src/toy.js:1)`); інакше — «не
бігло» (§7.12).

**TAP — теж мова з екрануванням** (рецензія 0046 R-1). Репортер node
пише `#` в імені як `\#`, а `\` як `\\`; `unescape_tap` знімає саме ці
два, і `fixes #12` чи `back\slash` читаються назад як самі себе.
Директива — перше **неекрановане** ` # ` після імені. Пробіл у кінці
імені — частина імені, і TAP його зберігає. Межа: символ керування
(табуляція, перенос) node пише як `\\t`/`\\n` — тими самими байтами,
що й буквальні `\t`/`\n`, — тож імʼя з таким символом назад не
читається; його вирок — «не бігло».

- `test_files`: `test/**` і `tests/**`, імена `*.test.{js,mjs,cjs,ts,mts}`.
  node збирає ширше — `*-test.*`, `*_test.*`, `test-*.*`, будь-що під
  `test/` — і ця межа названа в `keel check`.
- `unread_files`: решта сирців у `test/`/`tests/` — помічники,
  фікстури — названі поіменно.
- `module_paths`: `toy.bar` → `src/toy/bar.{ts,js,mjs,cjs,mts}`,
  `src/toy/bar/index.{ts,js}`, і те саме в корені: типізований перед
  простим, файл перед `index`. Крапки роблять теки, як у python; слеш у
  сегменті суд форми відкидає як «поза проєктом», порожній сегмент —
  не модуль.
- `run_test` жене `node --test --test-reporter=tap
  --test-name-pattern='^<імʼя>$' <файл>`. **Імʼя йде в регулярний
  вираз, тож екранується** (`escape_regex`): `a.b (x)` → `^a\.b \(x\)$`.
  Без цього `a.b` збігалось би з `axb`, а `(` ламала б бігун — урок
  хвилі 0044 про рядок, відданий чужій програмі. Імʼя іде окремим
  аргументом, не крізь шел — і це тримає проба з шимом `node`, що
  записує свій argv (рецензія 0046 R-8). Рядок для людини
  (`keel next`) — той самий, узятий в одинарні лапки з екранованим
  апострофом, тож `it's fine` вставляється в шел як є (R-5).
- `run_all` жене **по одному файлу** (TAP називає тест, а не файл) і
  бере з TAP і перелік, і вироки: `tap()` читає `ok`/`not ok N - імʼя`
  з YAML-блоком під ним (`---` … `type: 'test'|'suite'` … `...`).
  Рядок самого `describe` — `type: 'suite'`, у мапу не йде; `# SKIP`/
  `# TODO` — не бігло, у мапі нема. **Рядок для самого файлу — не
  тест, а червоний тест з іменем свого файлу — тест** (хвиля 0050):
  node друкує файл одним пройденим записом там, де в ньому нічого не
  бігло — файл без тестів, шаблон імені без збігу (`1..0`, потім `ok 1
  - <файл>`), — і фільтр за самим іменем викидав разом із ним червоний
  тест, названий як файл; хвиля закривалась над ним (глобальне ревʼю
  2026-09-06, R-21). Зміряно на node 22: рядок файлу ніколи не несе
  `location:`, тест, що впав, — завжди, а зелений — теж ні; тож
  червоне під іменем файлу — тест, а зелене вирішує читач оголошень:
  запис з іменем файлу, під яким сам файл **оголошує** тест
  (`test('<файл>', …)` — та сама рука `js_call`, що читає теги), — тест
  зі своїм вироком; запис, за який не відповідає жодне оголошення, —
  рядок файлу, поза мапою. Рецензія 0050 R-2 зміряла перший крій, де
  зелений тест з іменем файлу читався як рядок файлу: gate «проходить»,
  close «не виконала» — два суди про одне дерево. Ключ —
  `adapter::battery_key`.

## Дві речі, які мова робить інакше

**Перша: імʼя тесту — голе, і всередині `describe` теж.** TAP друкує
`ok 1 - inside`, а `--test-name-pattern='^inside$'` вибирає саме його
— `describe` не додає префікса, на відміну від ExUnit. Тож читач тегів
не стежить за блоками. Наслідок, названий вголос: два тести з одним
іменем у різних `describe` не розрізнити — ні тегом, ні бігуном; тож
обидва суди читають **усі** рядки з цим іменем, і будь-який `not ok`
серед них — червоне (рецензія 0046 R-2: ворота брали перший рядок і
благословляли `work:` над упалим тегованим тестом під другим
`describe`, поки `close` на тому ж дереві казав «червоний тест»).

**Читач тегів знає форми node:test** (рецензія 0046 R-3): `test(`,
`it(`, `test.only(`, `test.skip(`, `test.todo(` і їхні `it.`-двійники,
`await test(`, `const p = test(`, будь-яка ширина пробілу перед дужкою,
три види лапок з екранами. `.skip`/`.todo` — оголошення, як і опція
`{ skip: true }`: node каже `# SKIP`, суд — «не бігло». Дві речі тег
тримати не може, і відмова називає котру: **підтест** `t.test('…')` —
node жене його лише крізь батьківський `test` (зміряно:
`--test-name-pattern` з іменем підтесту не жене нічого, файл —
«1 пройдений»), тож тег ставиться на батька, чий вирок несе всі
підтести; та **імʼя, збудоване під час бігу** (`` `case ${n}` ``) — з
сирця його не прочитати.

**Друга: читач коментарів — четвертий, і не член родини `#`.** JS має
`//` і `/* */` як rust, але `'…'` тут рядок (у rust — час життя), а
шаблонний рядок у зворотних лапках біжить через кілька рядків. Малий
власний читач (`strip_js`): `//`, `/* */` (не вкладені), три види
лапок з екранами; звичайний рядок не переходить рядка. **Лапка, що не
закрилась на своєму рядку, — не рядок, а знак у коді**, і читання
триває одразу за нею (те саме рішення, що в ruby): апостроф у
регулярці чи в тексті JSX не ковтає решту рядка, і `const re =
/don't/; export function works() {}` тримає своє оголошення
(рецензія 0046 R-7 — попередня редакція казала «рядок — код», а
насправді решта рядка зникала). Один на js і ts, бо це та сама
робота. Межа: літерал регулярного виразу `/…/` не читається як
літерал — `//` усередині нього (`/^https?:\/\//`) відкриває коментар
до кінця рядка.

## Межі, названі вголос

- читається `test/` і `tests/` з одним іменем файлу; node збирає ширше;
- однакові імена в різних `describe` не розрізнити — читаються всі, і
  червоне серед них — червоне;
- підтест `t.test` тег не тримає — тег на батька; імʼя з `${…}` не
  читається;
- імʼя з символом керування (табуляція, перенос) з TAP назад не
  читається — «не бігло»;
- jest/vitest/mocha не читаються;
- `/…/`-літерали в суді форми не читаються як літерали: `//` у них —
  коментар;
- згенерований CI ставить `actions/setup-node` лише там, де проєкт
  тримає `.nvmrc` чи `.node-version`; інакше файл каже вголос, що
  судить node раннера (R-11).
