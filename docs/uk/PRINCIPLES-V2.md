# Keel — принципи (версія 2)

Одна сторінка. Читається завжди, перед будь-якою роботою.
Повний текст — у методиці v2, нормативному документі з нумерованими
параграфами; там кожне правило стоїть з причиною.

## 1. Стан виводиться, не пишеться

Що зроблено, а що ні — кажуть git і тести, не слова. Статуси руками не
проставляються ніколи.

## 2. Обіцянка перевіряється — або чесно записано, що ні

Сценарій стає тестом. Те, що перевірити нічим, записується
застереженням: «свідомо не робимо / не перевіряємо, і ось чому».

## 3. Тест народжується червоним

Commit `red: <сценарій>` проходить, лише якщо тест падає; commit
роботи — лише якщо тести зелені. Зелений тест, якого ніколи не бачили
червоним, не доводить нічого.

## 4. Файли називаються до роботи

Список файлів трансформи пишеться до коду. Вихід за список видно в
diff і в пакеті рецензента; тихий вихід заборонений.

## 5. Хто спирається на текст — тримає його редакцію

Редакція — короткий hash тексту. Текст змінився — перевірка дзвонить, і
зміна контракту тягне список впливу для рецензента. Це дзвінок, не
замок.

## 6. Обіцянка вміє померти

`withdrawn` з причиною — законна смерть; видалення файлів заборонене.
Історія не редагується — вона продовжується.

## 7. Мовчати не можна, відмовлятися — можна

Кожен із сорока розрізів якості отримує відповідь: закритий сценарієм
або вирішений з причиною. Тиші не існує — ні в плані, ні в ревʼю.

## 8. Церемонія — за вагою; памʼять — у git

Легка хвиля — один PR, повна — два. Сесія агента смертна, і це
нормально: свіжий агент відкриває репозиторій, питає `keel next` і
продовжує з того самого місця.
