# Файл у теці контрактів, який засіб не бачить, — і жодного слова про це

**Знайшла модель, не ми.** 25 серпня 2026 Ornith 1.5 промацувала `keel`,
щоб зрозуміти, як рахується редакція контракту. Створила файл і перевірила:

    $ cat > keel/contracts/reading_line.stubs <<'EOF'
    ---
    name: reading_line
    summary: "A raw line from the reading file is reduced to a structured value, or rejected."
    ---
    ## Contract
    Given something...
    EOF
    $ python3 keel/keel.py rev --write
    every revision matches
    $ python3 keel/keel.py gaps
    the plan is missing things (0001-readings-intake):
      … п'ять зауваг про хвилю, і **жодної** про контракт

Розширення вона взяла помилково — `.stubs` замість `.md`. Але засіб не сказав,
що помилка є. Він відповів так, ніби теки контрактів торкались правильно.

**Чому так.** `keel.py:1967`, обхід тек `waves` і `contracts`:

    for name in sorted(os.listdir(base)):
        if not name.endswith(".md"):
            continue

Усе, що не `.md`, зникає ще до розбору. Файл із коректним заголовком, іменем
і тілом контракту для засобу просто не існує — ні для `rev`, ні для `gaps`,
ні для `check`.

**Чим це небезпечно саме для агента.** Людина помітить, що файл не з'явився у
виводі. Модель робить протилежний висновок: вона спитала засіб, засіб відповів
`every revision matches`, отже редакції рахуються не так, як вона думала. Далі
вона планує з хибної моделі інструменту. Мовчанка тут гірша за відмову, бо
відмова вчить, а мовчанка вводить в оману.

**Той самий візерунок, що в [vada-check-ne-zviryaye-kontrakty-transforma].**
Засіб перевіряє лише те, що **названо**: там контракт, не вписаний у
`contracts:` трансформа; тут файл, не вписаний розширенням. В обох випадках
порожнеча читається як бездоганність.

**Чого бракує.** Заваги про видимий не-`.md` файл у `keel/waves` чи
`keel/contracts`: «лежить у теці, а засіб його не бачить».

**Тонкість, через яку це не однорядкова правка.** У тих теках законно можуть
бути `.gitkeep`, малюнки з `assets`, тимчасові файли редактора. Тому:

- крапкові імена пропускати мовчки;
- решту — попередженням, а не поламаним `check`, інакше чужий побічний файл
  спинятиме роботу;
- і, можливо, лише тоді, коли всередині є заголовок `---` з `name:` — тобто
  коли файл сам себе оголошує документом методики.

**Де лагодити.** У самому `keel`, з тестами. Норму спершу погодити: це нове
правило для `check`, а не лагодження зламаного.
