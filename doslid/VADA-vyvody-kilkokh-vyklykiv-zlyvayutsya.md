# Вада: виводи кількох викликів за хід зливаються без межі

**Знайдено:** 27 серпня 2026, прогін Ornith 1.5 35B на `0005-voda-plan`.

## Що видно

Модель робить кілька викликів одним ходом:

```lua
return tool.list("."), tool.list("keel"), tool.run("git status")
```

і дістає їх виводи склеєними через `\n`, без жодної позначки, який вивід чий:

```
[виклик list][виклик list][виклик run]
[програма]
Your program ran. It printed:

.formatter.exs        ← перший list
...
METHODOLOGY.md        ← другий list, межі не видно
```

Коли виводи багаторядкові, відповідність втрачається безповоротно.

## Чим це коштує

Ornith витратила частину ходу на з'ясування, що ж їй відповіли:

> «Wait, `git status` earlier returned... let me check. Earlier I ran
> `git status` and it printed the help? No. Let me re-check. Oh — actually
> my first batch included `run git status` and the output shown was the
> keel help. No wait, that was `keel/keel --help`. Let me re-read.»

Це не помилка моделі: за виводом справді не можна відновити, хто його дав.

## Чому не лагодиться в `Program.said/1`

Спокуса — пронумерувати значення в `session/program.ex:117`. Так робити не
можна: **кілька значень не означають кількох викликів**. `tool.run` повертає
пару (`nil` + причина) з одного виклику — тест `program_test.exs:97` це
закріплює. Нумерація значень збрехала б про `run`.

Межу вже названо в цьому ж файлі, коментарем при `show([])`:

> «виправляти це треба там, де відомо, хто повернув результат, — а не тут»

## Де лагодити

У шарі Lua, де виклик ще знає своє ім'я: обгортати результат кожного
`tool.*` так, щоб вивід ніс назву й аргумент виклику. Це зміна форми виводу
для всіх моделей — не правка на ходу, потрібне рішення й повторний вимір.

Пов'язане: [[VADA-skarhy-nazyvayut-vadu-ne-diyu]] — той самий рід вади,
вивід не називає себе.

## Гірший випадок, 28 серпня 2026: вивід не зливається, а зникає

Ornith-1.5-**9B**, той самий `0005-voda-plan`, режим native. Модель покликала
одним ходом `git status`, `git branch -a` і `git log`:

```
[виклик run][виклик run]
[програма]
Your program ran. It printed: Empty directory
```

Тобто від трьох команд git не лишилось нічого, а на їхньому місці стало
слово, яке належить іншому засобу — `show([])` із `session/program.ex:280`
віддає «Empty directory» на будь-який порожній список.

Модель відреагувала правильно й не повірила:

> The run command with `git status` returned "Empty directory"? That's odd…
> That's not a git command output. Wait — **maybe there's some
> interception**.

Вона має рацію: перехоплення справді сталося. Далі вона витратила кілька
ходів, перезапускаючи команди поодинці.

**Різниця з випадком 27 серпня.** Тоді виводи склеювались без межі — модель
не могла зіставити вивід із викликом, але кожен вивід був на місці. Тепер
вивід **підмінено чужим словом**: це вже не двозначність, а неправда про
стан світу.

**Межа була названа в коді заздалегідь** — `program.ex:274`:

> Межа названа: `tool.glob`, який нічого не знайшов, поверне ту саму порожню
> таблицю й покаже те саме слово. Це неточно, і виправляти це треба там, де
> відомо, хто повернув результат, — а не тут.

Отже місце ліку вже вказане: там, де відомо, який засіб дав результат.
