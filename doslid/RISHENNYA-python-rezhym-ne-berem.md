# Рішення: python-режим для планування не беремо

**Ухвалено:** 26 серпня 2026, Андрієм, після чотирьох моделей у двох режимах.

**Межа рішення:** воно про **планування**. Для написання коду режим треба
пробувати наново — там задача інша, і те, що робить його поганим тут, може там
виявитись перевагою.

## Чому не підходить саме для планування

Обіцянка режиму — одна програма замість десяти викликів: цикл, умова,
композиція. Планування такого не має. Тут послідовність: прочитай методику,
напиши хвилю, спитай засіб, виправ. Економити нема на чому — лишається сама
ціна.

## Числа

**Qwen3.6, той самий засіб, чотири прогони:**

| | native | python |
|---|---|---|
| результат | ✓ спроба 1 (двічі) | ✓ спроба 1 |
| ходів | 33 і 39 | 47 |
| час | 4,4 і 5,0 хв | **33 хв** |
| кеш | 90–96 % | **0 %** |

Режим не зменшив ходів — збільшив. Час зріс усемеро.

**Решта:**

- Devstral: native ✓ зі спроби 1 (49 ходів); python ✓ аж зі спроби 3 — дві
  спроби згоріли намарно (порожня заява «зроблено» за два ходи, тоді колапс
  повторення на пʼятнадцять хвилин).
- Laguna: native ✓ зі спроби 3; python ✓ зі спроби 1. Єдиний випадок, де python
  виграв, — і той пояснюється не режимом: Laguna створена для натівних
  викликів (`LAGUNA-natyvnyj-rezhym-ridnyj.md`), а native-прогін ішов зі
  старішим засобом.

## Три вади, які знайшлись саме в python-режимі

**1. Він ковтає відмови.** Кожен інструмент вертає пару `(значення, помилка)`.
Модель, що не взяла другого, відмови не бачить узагалі. Qwen3.6 у двох
прогонах поспіль писала:

    tool.write('keel/contracts/parse_readings.md', contract_content)
    print("Created keel/contracts/parse_readings.md")

Заслон відмовляв, файл не створювався — а вона друкувала своє «Created» і йшла
далі. У нативному режимі це неможливе: відмова приходить окремим повідомленням
із `is_error`.

Показово, що в тій самій програмі для `tool.run('git', ...)` вона помилку
**брала**. Тобто вміє — просто не робить там, де не чекає відмови.

**2. Колапс повторення.** Довга вільна генерація скочується в петлю: Devstral
надрукувала той самий блок 31 раз і забрала цілу спробу таймаутом. У native
виклик короткий, зациклитись ніде. (Полагоджено заслоном `Model.Loop`, але
сама схильність — властивість режиму.)

**3. Мертвий кеш на Qwen3.6.** Нуль кешованих токенів на кожному ході, префіл
17 секунд щоразу; у native той самий сервер кешує 90–96 %. Причина не знайдена
(див. `CHERGA-pravok.md`).

## Що режим таки дав

Він знайшов нам стіну, якої ми не бачили: перенесений на кілька рядків
YAML-список, що його читач не приймав. Шість прогонів двох різних ваг билися в
неї від 25 серпня мовчки (keel 0.8.29).

Тобто як **предмет досліду** він окупився. Як робочий режим для планування —
ні.
