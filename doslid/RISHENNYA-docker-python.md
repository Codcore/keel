# Рішення до розгляду: повний Python у Docker

**Поставлено:** 23 серпня 2026
**Стан:** дослідити й вирішити. Не зроблено.

## Звідки питання

Режим `code-python` за пʼять прогонів дав шість наших вад, і майже всі —
через **неповноту** пісочниці Pyex:

* модулі є, але часткові: `os` є, `os.getcwd` і `os.path.expanduser` немає;
* `subprocess`, `tempfile`, `unittest.mock` відсутні зовсім;
* власний файл проєкту не імпортується;
* рядки кодуються двічі, переліки приходять розверненими.

Mellum на цьому втратила **сорок ходів поспіль** — 39 разів той самий
`AttributeError` ([`MELLUM-39-raziv-odne-y-te-same.md`](MELLUM-39-raziv-odne-y-te-same.md)).

Повний Python у контейнері прибирає всі шість одним рухом.

## Важлива поправка: як ми стоїмо **зараз**

```elixir
Port.open({:spawn_executable, exe}, [args: args, cd: dir, env: nothing_but(opts)])
```

`tool.run("python3", ["test.py"])` запускає **справжній python3 на машині
людини, з її правами**. Заслон перевіряє лише:

* яку **програму** дозволено (`Command.allowed`);
* що **аргументи** не вказують за корінь проєкту.

**Вміст скрипта не перевіряється ніяк.** Він може читати `~/.ssh`, ходити в
мережу, писати поза `cd`.

Тобто сувора пісочниця стереже **розпорядника**, а `tool.run` — яким кожна
модель запускає тести — відчинений навстіж.

**Отже Docker не послаблює безпеку, а посилює:** він закриває дірку, яка вже є.

## Чесно про безпеку контейнера

Docker **не** є заслоном проти зловмисного коду: ядро спільне, втечі трапляються.

Але наша загроза інша — код **необережний**, а не ворожий. Для необережного
контейнера досить, якщо не лишати вмикання за замовчуванням:

| прапорець | що закриває |
|---|---|
| `--network=none` | `pip install` і витік назовні |
| `--read-only` + том лише на проєкт | усе поза проєктом |
| `--memory`, `--cpus`, `--pids-limit` | нескінченний цикл, форк-бомбу |
| `--cap-drop=ALL`, `--security-opt=no-new-privileges` | підвищення прав |
| не-root користувач | решту |

## Різниця в задумі

**Pyex:** заборонено все, крім переданого. Суворіше.
**Docker:** дозволено все, крім забороненого прапорцями. Придатніше.

Для стенда, де ми міряємо **моделі**, придатність важить більше: кожна наша
неповнота стає їхнім провалом, і ми міряємо себе.

## Що зважити перед впровадженням

1. **Ціна ходу.** Запуск контейнера — від пів секунди; тримати живим на сесію
   можна, але це стан, якого зараз немає.
2. **Що саме в контейнері.** Тільки `tool.run`? Чи весь режим `code-python`,
   тобто й розпорядник?
3. **Хто збирає образ.** Свій `Dockerfile` у стенді, чи офіційний `python:3.x`?
4. **Чи лишається Pyex.** Він може лишитись як **швидкий** режим для простих
   задач, де контейнер зайвий.
5. **Переносність.** Docker на машині людини є не завжди; `keel` не може від
   нього залежати беззастережно.
