# Вада: у Python інструменти треба імпортувати, і про це забувають

**Коли:** 23 серпня 2026, режим `code-python`
**Кого зачепило:** Mellum2-Thinking — втратила хід на першому ж рядку

## Що сталося

    the program did not run: python: NameError: name 'tool' is not defined (line 1)

У Lua інструменти глобальні: `tool.write(...)` працює одразу. У Python їх треба
імпортувати — і це зайвий крок, про який легко забути, надто коли модель уже
писала в іншому режимі.

## Що перевірено, перш ніж лагодити

Чи можна дати інструменти **без** імпорту. Три способи, усі три не годяться:

    modules: %{"builtins" => …}    ні
    modules: %{"__main__" => …}    ні
    env: %{"tool" => …}            ні

Pyex віддає модулі лише через `import`. Отже крок не прибрати.

## Лік

Не забирати крок, а не дати про нього забути: дописуємо `import tool` першим
рядком, якщо його немає.

```elixir
if Regex.match?(~r/^\s*(import\s+tool|from\s+tool\s+import)/m, code) do
  code
else
  "import tool\n" <> code
end
```

**Ціна названа:** номер рядка в помилці зсувається на одиницю там, де ми
дописали. Тому дописуємо **одним** рядком, а не двома — і згадуємо про це тут,
щоб не шукати потім розбіжність у півтори доби.

Свій власний імпорт лишається як був: двічі не дописуємо.

## Чому це не «підтерти за моделлю»

Межа тут така сама, як у `Model.Tools.code/2`, де ми складаємо назад програму,
порізану розбирачем сервера: **виправляємо форму, не вигадуючи змісту**. Модель
хотіла покликати `tool.write` — вона його й кличе. Ми лише не змушуємо її
пам'ятати рядок, який однаково має бути завжди.
