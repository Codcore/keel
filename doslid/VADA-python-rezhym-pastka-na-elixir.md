## Що модель писала

```python
tool.write("lib/tally.ex", """
defmodule Tally do
  @doc """          ← зовнішній рядок ЗАКРИВАЄТЬСЯ тут
  Count the occurrences...   ← а це вже розбирається як Python
```

Помилка, яку вона діставала тричі поспіль і не могла прочитати:

```
the program did not run: syntax: unexpected token at line 7: op::dot,
string:"\n  def count(text) do\n    |> String.downcase/1..."
```

Помилка називає **Elixir-код**, якого модель у Python не писала. З неї не видно,
що обірвався рядок, — видно тільки, що щось не так із чужим текстом.

## Вимір

| роздільник у Python-програмі | Elixir-файл із `@doc """` |
|---|---|
| `'''...'''` | працює — вернулось 79 байт |
| `"""..."""` | падає на розборі |

Перевірено прямим викликом `KeelAgent.Sandbox.Python.run/1`, обидві гілки.

## Чому це не вада Pyex

Pyex поводиться рівно як Python: `"""` закриває рядок на першій же трійці
лапок. Вада — у промті, який не сказав, що робити з мовою, чия документація
позначається так само.

## Порівняння режимів

| режим | як їде текст файлу | колізія з Elixir |
|---|---|---|
| `code-lua` | рівневі дужки `[==[ ... ]==]` | немає — і промт попереджає прямо |
| `code-python` | `"""..."""` | є — і промт мовчить |
| `native` | рядок у JSON | немає |

Тобто на питання «режими native і python однакові за можливостями?» відповідь
**ні**, і різниця вилазить саме на Elixir.
