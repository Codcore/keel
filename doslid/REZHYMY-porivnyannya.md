# Три режими виклику інструментів: що показали числа

**Коли:** 22–23 серпня 2026
**Випробування:** `0002-shopping` — «зроби командну штуку для списку покупок»,
порожня тека, вимога людськими словами.

## Що порівнювали

| режим | що бачить модель | де екранування |
|---|---|---|
| `code-lua` | один інструмент, аргумент — джерело Lua | у моделі, довгою дужкою |
| `native` | сім інструментів поіменно, аргументи — рядки JSON | у бібліотеці |
| без тулів | нічого не оголошено, блок у тексті | у моделі |

## Результат по суті завдання

Перевірено **читанням коду**, а не стовпчиком тестів: чи є стан «куплено» й
показ залишку окремо.

| ваги | `code-lua` + думка | `native`, без думки |
|---|---|---|
| гема | виконано, 5 ✓ | **виконано, 5 ✓** за 51с |
| Ornith | програма без тестів | **виконано, 16 ✓** |
| Laguna | програма без тестів | **виконано, 15 ✓** * |
| Qwen3.6 | 97 974 токени, нічого | **виконано, 29 ✓** |
| Mellum-Thinking | нуль двічі | **виконано, 3 ✓** |
| Mellum | нуль | 6 ✓, але `remove` замість позначки |
| Devstral | виконано, 5 ✓ | 5 ✓, але `remove_item` |
| Qwen3.8 | нуль, 7 прогонів | працює, повільно |
| GLM | програма, зрив | пакет, обрив |

\* у двох із трьох прогонів застрягала на `shell` до того, як довести тести

**`code-lua`: двоє виконали завдання з девʼяти. `native`: пʼятеро з семи.**

## Головне, чому так

`run_lua(code)` мав зняти екранування з моделі — і зняв лише зовнішній шар.
Аргумент був **джерелом Lua**, тож текст файлу модель однаково вкладала в рядок
Lua руками:

    {"code": "tool.write(\\"a.py\\", [==[def f(xs):\\n  return [x for x in xs if x[\\"ok\\"]]\\n]==])"}
     └─ JSON ─┘                    └──────── Lua, на моделі ────────┘

У `native` другого шару немає:

    {"path": "a.py", "text": "def f(xs):\\n  return [x for x in xs if x[\\"ok\\"]]\\n"}

Промт при цьому схуд із 4034 байтів до 1550 і не згадує Lua жодного разу.

## Чому це важить понад Python

Далі в плані Ruby, JavaScript, Elixir. Вкладення мови в мову **не лікується
вибором кращої мови-господаря**:

| що пишемо | у Lua `[==[ ]==]` | у Python `"""…"""` |
|---|---|---|
| Python | ламається на `x["ok"]]` | добре |
| Ruby | ламається на `]]` | добре |
| JavaScript | ламається на `a[b[i]]` | добре |
| **Elixir** | ламається | **ламається — у нього свої `"""`** |

`write(path, text)` від мови не залежить узагалі. Це аргумент за `native`
сильніший за будь-які наші числа.

## Чого `native` НЕ лікує

* **Моделі оголошують роботу зробленою.** Mellum і Devstral замінили «позначити
  куплене» на «видалити» — і написали зелені тести на спрощення.
* **Виклик чужим іменем.** Laguna кличе `shell` замість `run`; сімнадцять
  прямих вказівок не змінили нічого.
* **`finished` і `too_many_turns` не кажуть про зроблене.** Laguna записана
  провалом, маючи пʼятнадцять зелених тестів.

## Що лишається невипробуваним

* `native` **з думкою** — пройшла лише Laguna (див. нижче), решта в черзі;
* `code-python` через Pyex — третій режим, ще не існує;
* Laguna з думкою на офіційних параметрах (їхні числа — для режиму думки).

## Laguna з думкою: один прапорець перевернув усе

23 серпня, `native`, ті самі ваги й параметри — змінено рівно `thinking`:

| | без думки ×3 | з думкою |
|---|---:|---:|
| `shell` (інструмент, якого немає) | **36 із 45** | **1** |
| `edit` | 0 | **19** |
| `read` | 0 | **21** |
| тести | 12 червоних | **9 зелених** |
| завдання по суті | частково | **виконано** |

Параметри Poolside дають саме **для режиму думки** — і тільки в ньому модель
поводиться так, як задумано: читає файл перед правкою, править точково, майже не
вигадує чужих інструментів.

**Через це довелось спростувати два власні записи:**

* «`shell` — стала поведінка цих ваг» — ні, поведінка **в чужому режимі**;
* «Laguna не чує поради про `edit`» — чує, 19 разів.

**І це ставить під сумнів решту нулів.** Mellum, гема й Ornith у `native`
ганялись **тільки без думки**. Доки не пройдуть із нею, їхні числа кажуть про
режим, а не про ваги.


## Перевірка, поставлена навмисно: Mellum-Instruct із прапорцем думки

Звичайний Mellum думати не вміє — і саме тому його прогнали з `THINK=true`.

**Що це розділяє.** Прапорець у нас стає `reasoning_effort: :medium` у запиті, а
сервер підставляє `enable_thinking` у шаблон розмови. Тобто змінюється **дві**
речі: сама думка й форма запиту.

Модель, якій нема чим думати, покаже другу окремо:

* якщо поведінка зміниться — річ була не в роздумах, а в тому, що ми шлемо;
* якщо ні — ефект Laguna справді від думки.

Без цієї пари висновок «думка перевертає все» тримався б на одному розіграші
однієї моделі.

### Результат: прапорець зробив **гірше**

| Mellum-Instruct, `native` | ходи | час | файли |
|---|---:|---:|---|
| без думки | 16 | 64с | обидва, 6 зелених |
| **з прапорцем** | **2** | **20с** | **жодного** |

Хід другий, дослівно:

    [МОДЕЛЬ] Let me create the project structure for the shopping list app with tests.

І тиша. Подивився, оголосив намір — і цикл зарахував це за кінець, бо після
погляду відповідь словами є законним висновком.

**Що це означає.** Ефект Laguna був **не** від зміни форми запиту: та сама зміна
на моделі без роздумів дала протилежне. Отже там справді працювала думка.

**І окремо:** прапорець `enable_thinking` вагам, які його не мають, шкодить.
Модель починає поводитись так, ніби вже все обміркувала, і завершує хід
оголошенням наміру.
