# Наш вимір брехав про результат прогону

**Спіймано:** 23 серпня 2026, на прогоні Qwen3.6, який завершився чисто.

## Що було

Журнал:

```json
{"kind": "ending", "body": {"stop": "finished", "turns": 2, "took_ms": 112386}}
```

Наш звіт:

```
Qwen3.6: ходів 3, стоп unchecked
```

Тобто **найкращий прогін вечора** — два ходи, дванадцять зелених тестів, повна
документація — записався як провал заслону доказу.

## Причина

`tools/measure.py`, `stop_reason/1`:

```python
for row in reversed(rows):
    text = json.dumps(row.get("body") or {}, ensure_ascii=False)
    for name in ("too_many_turns", "unchecked", …):
        if name in text:
            return name
```

Пошук **підрядком у всьому JSON** кожного запису. Слово «unchecked» трапилось
десь у тексті самої моделі — і вимір узяв його за причину зупинки.

## Чому це небезпечніше за звичайну ваду

Вада тиха й **однобічна**: вона перетворює успіх на провал, але не навпаки.
Тобто всі наші таблиці могли занижувати результати, і помітити це можна лише
звіривши з журналом руками — що я й зробив випадково, побачивши розбіжність з
оком.

## Лік

Читати **запис про кінець**, який журнал і так пише:

```python
for row in reversed(rows):
    if row.get("kind") != "ending":
        continue
    body = row.get("body") or {}
    if body.get("stop") == "failed" and body.get("reason"):
        return str(body["reason"]).strip("{}: ").split(",")[0].strip(": ")
    return body.get("stop") or "ok"
```

Перевірено на трьох прогонах: `finished`, `finished`, `too_many_turns` — усі
збігаються з тим, що показує `mix agent.log`.

## Урок

**Не шукай стан підрядком у тексті, коли є поле.** Журнал писав правду весь
час; брехав той, хто її читав.

І ширше: розбіжність між двома джерелами — оком і виміром — виявилась
кориснішою за кожне з них окремо. Варто звіряти їх навмисно, а не випадково.
