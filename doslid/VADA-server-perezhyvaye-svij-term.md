# Вада: сервер переживає TERM і тихо краде порт у трьох наступних моделей

**Коли:** 23 серпня 2026, 21:57–22:05 UTC
**Де:** `tools/sweep.sh`, прибирання між моделями
**Ознака:** один рядок серед звичайного галасу

```
ERROR: [Errno 48] error while attempting to bind on address ('127.0.0.1', 8911): address already in use
```

## Що сталось

`pkill -f "mlx_lm.server"` послав TERM. Сервер із Mellum-Thinking його
**пережив** — і лишився жити:

```
PID 206  STAT RN  RSS 9.4 ГБ  mlx_lm.server --model Mellum2-12B-A2.5B-Thinking-6bit
lsof: python3.1 206  TCP 127.0.0.1:8911 (LISTEN)
```

Далі кожна наступна модель піднімала свій сервер, діставала `Errno 48` і
пропускалась. Втрачено три поспіль: **Mellum-Thinking, гема, Laguna**.

Mellum-Thinking втратився інакше за решту: його сервер помер уже **під час**
прогону, і агент дістав `econnrefused` на першому ході. Журнал 2129 байт.

## Чому не помітили відразу

Гема пропалась мовчки. У логу це виглядає так:

```
########## gemma-4-26b-qat-4bit ##########
  СЕРВЕР НЕ ПІДНЯВСЯ — пропускаю
ERROR: [Errno 48] ...
########## laguna-xs-2.1-4bit ##########
```

Рядок `СЕРВЕР НЕ ПІДНЯВСЯ` є, і він правдивий, — але не називає причини, а
причина стоїть **після** нього, серед звичайних INFO сервера.

## Гірше за пропуск

Мертвий сервер **відповідав** на `/v1/models` — вагами Mellum-Thinking.
Заслон готовності для `srv=lm` тільки цю відповідь і питає:

```bash
if [ "$srv" = "lm" ] || grep -aq "Uvicorn running" "$SRVLOG"; then ready=1
```

Тобто прогін геми міг піти **на вагах Mellum-Thinking** і порахуватись
успішним. Врятувало те, що для `mlxsrv_lenient` є друга умова — рядок у
власному логу сервера. Для `mlx_lm.server` такої умови немає, і це наступне,
що треба лікувати.

## Лік

Вихід визначає **порт**, а не сигнал:

1. TERM усім;
2. поки на `$PORT` хтось слухає — чекати, до 24 секунд;
3. на дванадцятій секунді — KILL;
4. якщо порт так і зайнятий — сказати вголос і пропустити модель **свідомо**.

`lsof -sTCP:LISTEN` питає ядро про порт, а не `pgrep` про рядок команди: сервер,
який не помер, порт тримає незалежно від того, як його звати.

## Чого це не лікує

Заслон готовності для `srv=lm` досі вірить самій лише відповіді `/v1/models`.
Поки порт звільняється чесно, цього досить; коли ні — модель піде на чужих
вагах. Записано окремо, лікувати після прогонів.
