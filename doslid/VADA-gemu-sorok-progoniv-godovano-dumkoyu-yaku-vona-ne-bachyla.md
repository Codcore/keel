# Гему сорок прогонів годовано думкою, яку її шаблон вирізає

**Знайдено:** 29 серпня 2026, оператором — «іі думку точно не треба вертати?
глянь оф картку може ще нюанси є».

## Що з'ясувалось

Думку в історію ми кладемо тегами `<think>` усередину `content`. Шаблон
Gemma 4 їх не просто не читає — він їх **вирізає**:

```jinja
{{- strip_thinking(message['content']) -}}      ← рядки 339 і 347
```

А бере він її звідки завгодно, крім `content`:

```jinja
{%- set thinking_text = message.get('reasoning') or message.get('reasoning_content') -%}
{%- if thinking_text and loop.index0 > ns_turn.last_user_idx and message.get('tool_calls') -%}
    {{- '<|channel>thought\n' + thinking_text + '\n<channel|>' -}}      ← рядок 259
```

Тобто прапорець «думку зберігати» міг стояти скільки завгодно: до моделі вона
не доїжджала **жодного разу**. Кожен хід гема починала наосліп — думала, і
наступного ходу тієї думки не бачила.

## Чого це коштувало

За цим стояв профільний вимір, записаний як властивість ваг:

```
  з думкою   38 ходів  24379 токенів  695 с  → 2 зелені
  без думки  34 ходи   12633 токени   403 с  → 3 з 4
```

Звідси в профілі стояло `думка.треба: false`, а в наших висновках — «гема
зривається, колапс повторень, чекати від неї доведеної роботи не варто».
Прогонів під цим висновком набралось близько сорока.

Вимір недійсний: він порівнював «без думки» з «думка є, але не доходить» —
а це гірше за обидва справжні режими. Модель платила токенами за міркування,
якого потім не мала.

## Що каже сама Google

Картка Gemma 4 називає правило прямо, і воно **не двійкове**:

> in multi-turn conversations, the historical model output should only include
> the final response, with thoughts from previous model turns not to be added
> before the next user turn begins, **with the exception of tool call turns
> where thinking content should be preserved**

Рядок 259 шаблону — те саме правило машиною. Звідси наш обов'язок рівно один:
слати думку **полем** у кожному ході асистента. Вибирати, де її лишити, не
наша справа — шаблон сам візьме її тільки в ходах із викликом інструмента й
тільки після останнього повідомлення користувача.

## Лік

У профілі ваг:

```json
"думка": { "зберігати": true, "як": "field", "треба": true }
```

Механізм уже був — його зробили 28 серпня для North-Mini-Code, чий шаблон так
само не знає тегів. `thinking_as: :field` вішає гачок `on_finch_request`, який
виймає думку з тегів, кладе в `reasoning_content` і прибирає з тексту, щоб не
поїхала двічі.

**Перше, що зробила гема після ліку:** за чотирнадцять викликів — план, хвиля
й два контракти (`flats`, `previous-readings`, тобто входи, на які хвиля
спирається). Доти перший контракт з'являвся аж на вісімнадцятому ході.

## Сторожа

`tools/test_params_dumka.py` — профіль мусить називати той спосіб доставки,
який шаблон цих ваг справді читає, і ніде не може стояти «полем» без
«зберігати».
