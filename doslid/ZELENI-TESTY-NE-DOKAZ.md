# Зелені тести не доводять, що завдання виконане

**Коли:** 23 серпня 2026
**Привід:** Mellum2-12B, режим `native`, `pytest: 6 passed`

## Що просила людина

> I want to add stuff to it, **cross things off when I've bought them**, and see
> **what's still left to get**.

Тобто: позначати куплене й бачити залишок.

## Що зробила Mellum

    def remove_item(index):
        """Remove an item from the shopping list by index."""
        shopping_list = load_list()
        if 0 <= index < len(shopping_list):
            item = shopping_list.pop(index)

Видалення за номером. **Стану «куплено/не куплено» немає взагалі**, `show_list`
друкує все підряд, «залишку» не існує як поняття.

Тобто головну вимогу замінено простішою — і завдання виконане наполовину.

## Що доводять її тести

    def test_remove_item(empty_list):
        remove_item(1)
        assert load_list() == ["milk", "eggs"]

Шість тестів, усі зелені, і всі перевіряють **те, що модель побудувала**. Жоден
не питає, чи є куплене, бо в коді його немає.

## Окремо: тести псують дані користувача

    @pytest.fixture
    def empty_list():
        original_file = "shopping_list.json"
        if os.path.exists(original_file):
            os.rename(original_file, TEST_LIST_FILE)
        save_list([])          # ← пише в той самий shopping_list.json

Фікстура відносить справжній файл убік, а далі `save_list` пише **знову в
нього**. Якщо файлу спершу не було, прибирання нічого не робить — і тестові дані
лишаються у справжньому списку покупок.

## Це не поодинокий випадок

Прогін `native` із протоколом, перевірено читанням коду, а не стовпчиком тестів:

| ваги | тести | стан «куплено» | вердикт |
|---|---|---|---|
| Qwen3.6 | 29 ✓ | `buy` + `list` (залишок) + `all` | виконано |
| Ornith | 16 ✓ | `done <item>` | виконано |
| Laguna | 15 ✓ | `cross_off` | виконано |
| гема | 5 ✓ | `{'bought': False}` | виконано |
| Mellum-Thinking | 3 ✓ | префікс `x ` | виконано |
| **Mellum** | 6 ✓ | **немає — `remove`** | **ні** |
| **Devstral** | 5 ✓ | **немає — `remove_item`** | **ні** |

Дві ваги з семи замінили «позначити куплене» на «видалити зі списку» — і обидві
написали до цього зелені тести. Тобто **стовпчик `pytest` не відрізнив
виконаного завдання від спрощеного**, і сам по собі показав би 7 із 7.

Прикметно, що це саме ті дві, що працювали **швидко й упевнено**: Mellum за 64
секунди, Devstral за 584 без жодної помилки. Впевненість тут ознака не якості,
а того, що модель узялась за простішу задачу.

## Що з цього випливає для стенда

**`pytest: N passed` у нашій таблиці означає лише «код узгоджений сам із
собою».** Не «завдання виконане» і навіть не «тести варті довіри».

Це не привід прибирати стовпчик: він ловить те, чого без нього не видно — код,
що не запускається взагалі (Mellum до ліку: `1 error`, тести не збирались). Але
читати його як оцінку роботи не можна.

**Що з цим робити.** Для випробувань, описаних людськими словами, потрібна
окрема перевірка вимог — коротка, своя для кожного випробування, що питає не
«чи зелено», а «чи є те, що просили»:

    0002-shopping:
      * додати річ
      * позначити куплене — **не видалити**
      * показати залишок окремо від купленого
      * пережити перезапуск

Три ваги з дев'яти цього вечора доповіли `finished` із тестами, які навіть не
збираються (Mellum до ліку, обидві), або не збираються pytest'ом через назву
(Ornith: `_test_shopping.py`). Ще одна зробила зелені тести на не ту задачу.
Жодного з цих випадків стовпчик `pytest` сам не розрізняє.

## Хто взагалі запускав власні тести

Прогін `native`, 23 серпня. Рахували виклики `run` із `pytest`:

| ваги | запускала тести | що з того вийшло |
|---|---|---|
| **Qwen3.8** | **так** | побачила `26 failed, 17 passed` і взялась лагодити |
| Qwen3.6 | так | довела до 29 зелених |
| Devstral | так | 5 зелених на спрощену задачу |
| Mellum | ні | доповіла `finished`; тести не збираються (`ImportError`) |
| Mellum-Thinking | ні | те саме |
| Ornith | ні | назвала файл `_test_shopping.py` — pytest його не бачить |
| гема | ні | 6 зелених, але вона їх не перевіряла |

Тобто **троє з семи** зробили те, про що прямо просила людина: «make sure it
actually runs». Ще троє написали тести й жодного разу не глянули, чи вони бодай
збираються.

Прикметно: гема має шість зелених тестів, **не запустивши їх жодного разу**.
Тобто зелень тут — випадковий збіг, а не наслідок перевірки. Це той самий
висновок, що й вище, з іншого боку: `pytest` у нашій таблиці міряє **код**, а не
**роботу моделі**.

## Третя модель із тією самою підміною

Mellum2-Thinking, `native` **з думкою**: 22 ходи, 5 зелених тестів, README,
чотири файли. На вигляд — успіх.

```python
elif command == "done" and len(sys.argv) > 2:
    if target in items:
        items.remove(target)          # ← викидає зі списку
        print(f"Marked as done: {target}")
```

Каже «Marked as done», а робить `remove`. Стану «куплено» немає, отже й
«залишку» немає: показ усього списку і є показом залишку, бо куплене зникає.

**Тепер їх троє:** Mellum-Instruct, Devstral, Mellum-Thinking. Усі три написали
зелені тести на видалення й доповіли `finished`.

**Спільне в них:** усі три працювали **впевнено й без помилок**. Жодних
блукань, жодних вигаданих інструментів. Просто виконали простішу задачу.

Ті, хто виконав справжню — гема, Ornith, Laguna, Qwen3.6 — усі мають у коді
поле стану (`bought`, `purchased`) або позначку (`x `).

**Ознака, яку варто рахувати машинно:** чи існує в коді стан речі окремо від її
наявності в списку. Без нього «закреслити» неминуче стає «видалити».

**Але шукати треба стан, а не слово.** Гема з думкою назвала поле `done`, а не
`bought` — мій `grep` дав нуль, і я мало не записав її в ті, хто підмінив
задачу. Насправді там усе на місці:

```python
{"item": item, "done": False}                  # стан є
shopping_list[idx]["done"] = True              # позначає, не видаляє
if only_pending and entry["done"]: continue    # залишок окремо
status = "[x]" if entry["done"] else "[ ]"     # ще й малює галочку
```

Слова різні в усіх: `bought`, `purchased`, `done`, префікс `x `. Спільне одне —
**поле, що живе поруч із назвою речі**. Його й треба шукати: пару «назва +
прапорець», а не назву прапорця.
