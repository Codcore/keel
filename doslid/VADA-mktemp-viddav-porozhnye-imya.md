# Вада: mktemp віддав порожнє ім'я, і три прогони «скінчились» за секунди

**Коли:** 23 серпня 2026, 22:20 UTC
**Де:** `tools/queue.sh`, зняття копії `sweep.sh`
**Ознака:** черга відрапортувала успіх, не виконавши нічого

```
[черга] /tmp/sweep-uk-py.log ← TOOLS=python …
[черга] /tmp/sweep-uk-py.log готово        ← за секунду
[черга] /tmp/sweep-en-py.log готово        ← за секунду
[черга] /tmp/sweep-q36-128k.log готово     ← за секунду
########## УСЕ СКІНЧЕНО ##########
```

У логах прогонів лежало по 34 байти:

```
bash: : No such file or directory
```

Порожнє ім'я між двокрапками — це `bash ""`.

## Чому

```bash
copy=$(mktemp /tmp/sweep-copy-XXXXXX.sh)
```

BSD `mktemp` вимагає, щоб `XXXXXX` стояли **в кінці** шаблону. Тут після них
іде `.sh`, тож ім'я бралось буквально: файл так і звався
`sweep-copy-XXXXXX.sh`. Перший раз це працювало — файл створювався. Другий раз
такий файл уже існував, і `mktemp` **мовчки** віддав порожній рядок замість
помилки.

## Чому шукав не там

Я щойно перед тим вибивав залишки старих прогонів шаблоном `[s]weep-copy` — і
вирішив, що сам себе й підрізав. Ознака була та сама: щойно запущене миттєво
зникає. Різницю показав лише вміст логу: убитий процес лишає обірваний вивід,
а тут стояв рівний рядок про ненайдений файл.

## Лік

```bash
copy=$(mktemp /tmp/sweep-copy-XXXXXX) || { echo "mktemp не дав файлу" >&2; return 1; }
[ -n "$copy" ] || { echo "mktemp віддав порожнє ім'я" >&2; return 1; }
```

X-и в кінці, розширення прибране — bash його не потребує. Плюс перевірка на
порожнє: мовчазна відмова більше не проходить далі.

Перевірено: два виклики поспіль дають різні імена (`sweep-copy-3aIUdw`,
`sweep-copy-l5WRVc`).

## Урок

Команда, що вміє віддати порожнє замість помилки, мусить мати перевірку на
порожнє. `set -u` тут не рятує: змінна **встановлена**, просто порожня.
