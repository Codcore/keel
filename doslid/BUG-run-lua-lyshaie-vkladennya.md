# Вада задуму: `run_lua(code)` лишає вкладення мови в мову

**Коли:** 23 серпня 2026
**Де:** `agent/lib/keel_agent/model/tools.ex` — оголошено один інструмент
**Кого зачепило:** усіх, хто пише файл: гема, GLM, Qwen3.8, Laguna, Mellum

## Що ми собі пообіцяли

У `moduledoc` записано так:

> Тож зміст лишається наш, а розмітка стає рідною для моделі: код їде полем
> JSON, і екранування робить бібліотека, а не модель у `[[...]]`.

## Що вийшло насправді

Бібліотека екранує **зовнішній** шар — Lua. Python усередині Lua лишився на
моделі, бо аргумент нашого інструмента — це **джерело Lua**, а не текст файлу.

Qwen3.8, 23 серпня, хід четвертий. Виклик правильний, натівний, код у полі JSON:

    хід 4: ВИКЛИК run_lua ключі=['code'] 15044 симв

І він не виконується:

    the program did not run: line 453: Unclosed long string [[...]]

Бо всередині коду:

    assert "empty" in out
    ==]                      ← мало бути ]==]
    return "files written"
    ==])                     ← і тут

Модель **відкрила `[==[` двічі, закрила `==]` двічі** — без першої дужки.
Порада про рівневі дужки навчила її половини.

## Ланцюг, який видно з цього повністю

Усі три ліки цієї ночі били по одному й тому самому місцю, не зачіпаючи його:

1. `[[ ]]` ламалось об `x["ok"]]` у Python → порадили `[==[ ]==]`
2. `[==[ ]==]` гема й GLM узяли, Qwen3.8 закриває його з помилкою
3. натівний виклик прибрав загородження ```lua — і не прибрав нічого більше

Спільна причина одна: **щоб покласти файл на диск, модель мусить укласти чужу
мову в рядок Lua**. Хай як ми звемо ту дужку, вона лишається.

## Лік, якого ще не зроблено

Оголосити натівно ті інструменти, які беруть **текст**, а не код:

    write(path, text)     ← Python їде рядком JSON, екранує бібліотека
    edit(path, old, new)
    read(path), list(path), grep(text), glob(pattern), run(program, args)

`run_lua(code)` лишається поруч — для ходу, де треба кілька дій і розгалуження
між ними. Тобто не заміна, а другий шлях.

**Заперечення, яке треба зважити:** у `moduledoc` записано, що сім інструментів
означали б втрату головного — програми з кількома діями за хід. Це правда для
**заміни**, але не для співіснування: модель, яка хоче написати файл і одразу
запустити тести, кличе `run_lua`; модель, яка хоче просто покласти файл, кличе
`write` і не платить за це вкладенням мов.

Числа на користь: Mellum, Laguna й Qwen3.8 самі, без підказки, кликали `write`,
`list`, `run` поіменно — ми вже приймаємо ці виклики й перекладаємо в Lua
(`Tools.code/2`). Тобто половина шляху пройдена: приймаємо сім, оголошуємо один.

**Не зроблено.** Це зміна задуму, не лік вади, і рішення за людиною.
