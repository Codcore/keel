# `tool.run` із іменованим ключем вивалює сторінку Elixir у розмову

**Спіймано:** 22 серпня 2026, прогін GLM-4.7-Flash, `python/0001-fold-ranges`.

## Що зробила модель

Передала другим аргументом таблицю з **іменованим ключем** замість списку:

```lua
local status = tool.run("pytest", {path = "tests"})
```

Помилка моделі — так, наш `tool.run` чекає список рядків: `{"tests"}`.


Майже кілобайт документації Elixir — у контекст моделі, яка не знає ні Elixir,
ні наших протоколів. Наступний хід вона витратила на спроби зрозуміти, що це
було:

> Уявлю, що `tool.run` приймає рядок або таблицю, де ключ — назва програми…

Тобто здогад пішов **у хибний бік**, бо в повідомленні немає жодного слова про
те, чого насправді бракує.

## Чому це наша вада, а не її

Помилку в аргументі робить модель, але **повідомлення пишемо ми**. Зараз воно:

- не називає, який аргумент негодящий;
- не каже, яким він має бути;
- натомість вивалює внутрішній протокол серіалізації, якого модель не бачила
  й бачити не мала.

Кожен такий випадок — це втрачений хід і кілобайт зіпсованого контексту.

## Що мало б бути

```
tool.run: другий аргумент має бути списком рядків, а не таблицею з ключами.
Було: {path = "tests"}. Треба: {"tests"}
```

## Де це живе

Помилка виникає при кодуванні значення з Lua назад у JSON для журналу й
розмови. Тобто лік — перевірити аргументи **до** виклику, а не покладатися на
те, що серіалізатор поскаржиться сам.

**Не полагоджено.** Це вада, і за домовленістю її можна лагодити відразу — але
вона в `keel-agent`, а не в цьому репозиторії досліду, і зачіпає спільний шлях
кодування. Тож чекає на рішення.
