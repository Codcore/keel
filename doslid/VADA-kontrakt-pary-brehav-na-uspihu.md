# Вада: промт учив розпаковувати пару, а успіх вертався рядком

**Коли:** 23 серпня 2026, 21:53 UTC

**Ціна:** Mellum-Thinking — 2 ходи, 60 секунд, жодного файлу

## Що обіцяв промт

```python
text, err = tool.read("main.py")
if text is None:
    print("could not read:", err)
```

## Що робив код

```elixir
defp answer({:ok, value}), do: given(value)              # успіх → рядок
defp answer({:error, reason}), do: [nil, given(reason)]  # відмова → пара
```

Тобто написане в промті працювало **лише на відмові** — на тому шляху, яким
нічого не виходить. На успішному воно ламалось:

```
ValueError: not enough values to unpack (expected 2, got 2403)
```

2403 — це довжина прочитаного файлу. Python розібрав рядок посимвольно.

## Звідки взялось

Контракт списаний із Lua, і коментар це визнавав: «Відмова вертається парою,
як і в Lua». У Lua `local text, err = tool.read(…)` працює обома шляхами —
мова розпаковує стільки, скільки є. Python так не вміє, і перенесення
контракту без перевірки коштувало прогону.

## Лік

Пара **завжди**: `(значення, None)` або `(None, причина)`. Промт вирівняний під
неї — приклади в ньому теж розпаковують.

## Перевірено

Тест ганяє обидва шляхи на живому Pyex: успішне читання дає `text= True,
err= None`, невдале — `text= None, err= True`. Без ліку тест **червоніє** —
перевірено вимкненням. 469 тестів зелені.

## Ціна названа

Хто пише `text = tool.read(path)` без розпакування, дістане пару замість
рядка. Промт учить інакшого, тож така модель помилялась би й до цього; але
помилка стала іншою на вигляд, і в старих прогонах її не шукати.
