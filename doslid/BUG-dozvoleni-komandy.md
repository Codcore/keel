# Випробування просить запустити те, що заслон забороняє

**Спіймано:** 22 серпня 2026, `0002-shopping`, на прогоні Laguna.

## Що дозволено

`config/config.exs`, `KeelAgent.Tools.Command`:

```elixir
allowed: [
  ["python3", "keel/keel.py", "next"],     # і ще чотири підкоманди
  ["mix", "test"], ["mix", "compile"], …
  ["pytest"], ["python3", "-m", "pytest"],
  ["git", "status"], …
]
```

`python3` дозволений **виключно** з прибитим `keel/keel.py`. Це перелік для
роботи над самим Keel — і він лишився з попереднього випробування.

## Наслідок перший: завдання нездійсненне як поставлене

Людина просить:

> Make sure it actually runs, I want to use it.

Модель фізично не може виконати `python3 shopping.py`. Заслон відкине команду
зі словами «running «python3 shopping.py» is not allowed».

## Наслідок другий: примара `keel/keel.py`

Дозволений перелік іде в system prompt дослівно. Моделі читають там
`python3 keel/keel.py next` — і **вважають, що цей файл існує**.

Laguna півтори тисячі токенів шукала його: `glob('keel/*.py')`,
`tool.list('keel')`, `glob('keel')`. GLM у попередньому випробуванні писала
`tool.run('python5.5', { 'keel/keel.py next' })`.

Тобто перелік дозволеного працює як **фальшива підказка про будову проєкту**.

## Наслідок третій: pytest — дірка в заслоні

Гемма завдання виконала. Але запускала свою програму так:

```python
subprocess.run(["python3", "shopping.py"], capture_output=True, text=True)
```

всередині тесту. `pytest` дозволений, а що він робить усередині — ми не
перевіряємо ніяк. Тобто **через pytest можна запустити будь-що**.

Це не вада гемми: вона шукала спосіб виконати прохання й знайшла єдиний
доступний. Але заслон, який зупиняє `python3 shopping.py` і пропускає
`pytest`, що робить те саме, охороняє не те, що думає.

## Що з цим робити

Для випробування — дати кожному свій перелік дозволеного. `0002-shopping`
потребує принаймні `python3` без прибитого файла.

Для агента — окреме питання, і воно неприємне: **чи має сенс білий перелік
команд, якщо одна з дозволених уміє запускати все**. Відповідь не очевидна:
прибрати pytest не можна, він потрібен; перевіряти, що всередині тестів, —
неможливо.

**Не полагоджено.** Перше — правка прогону, зроблю зараз. Друге — норма, і
воно ваше.


## Devstral прочитала перелік як «це проєкт на Elixir»

22 серпня, `0002-shopping`, перший хід. Людина просила «командну штуку для
списку покупок» і не називала жодної мови. Devstral написала **Elixir**:

```
To use it:
- `mix run shopping_list.exs add <item>`
- `mix run shopping_list.exs list`
```

Звідки Elixir? З нашого ж переліку дозволеного, який іде в system prompt
дослівно:

```
mix test, mix compile, mix format, mix credo, mix ci
python3 keel/keel.py next|check|gaps|show|rev
```

П'ять команд `mix` проти двох про Python — і модель зробила очевидний
висновок про те, який це проєкт.

**Це друга форма тієї самої вади.** Перша: моделі шукали `keel/keel.py`, бо
він названий у переліку. Друга: моделі пишуть на Elixir, бо переважає `mix`.

Перелік дозволених команд задумувався як **заслон** — що можна запускати. А
працює він ще й як **опис проєкту**, якого ніхто не писав і який здебільшого
брехливий.

## Що з цього випливає

Перелік дозволеного треба або задавати **під випробування** (для `0002` це
`python3`, `pytest`, і нічого зайвого), або показувати моделі інакше — не
переліком конкретних команд, а правилом, з якого не видно чужого проєкту.
