# Два `cat` за хід згорали: «only a single shell command runs here»

**25 серпня 2026, Ornith.** Вона попросила два файли одним ходом:

    cat keel/QUALITY.md
    cat .keel-agent/skills/keel-plan/SKILL.md

і дістала відмову. Хід згорів на найкориснішій дії, яку модель узагалі може
зробити на локальних вагах.

**Механізм.** `Tools.program/1` існує саме для цього — щоб хід не коштував по
одній дії. З двох викликів він складає програму:

    local out = {}
      out[#out + 1] = tool.shell("cat keel/QUALITY.md")
      out[#out + 1] = tool.shell("cat .keel-agent/skills/keel-plan/SKILL.md")
    return out

А прямий шлях режиму `shell` розбирав рівно одну форму:

    ~r/^return tool\.shell\((.*)\)$/s

Складена програма під неї не підходить — і не виконувалось нічого.

**Ціна.** У Ornith TTFT 25 секунд на промпті в 15 тисяч. Кожен такий хід — це
пів хвилини за нуль, ще й з відповіддю, яка радить робити гірше: по одному
файлу за раз.

**Полагоджено.** Приймаються обидві форми — одна команда й складена програма.
Результати вертаються переліком, по рядку на команду, як і в натівному шляху.
Чужий виклик у програмі так само не пускається, і не пускає сусідів: виконати
половину означало б зробити частину роботи й змовчати про решту.

**Тести** (`server_test.exs`, режим `:shell`, натівні `tool_calls`):

    ✓ два виклики shell за хід виконуються обидва
    ✓ команди йдуть у тому порядку, в якому написані
    ✓ у складеній програмі чужий виклик спиняє всю

**Урок.** Тест на режим `shell` був — але він слав команду **блоком Lua**, а не
натівним викликом, і тому не бачив ані цієї вади, ані сусідньої
([BUG-vidmova-superechyla-sobi]). Тест мусить іти тим шляхом, яким ходить
модель.
