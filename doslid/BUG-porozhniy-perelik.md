# Порожній результат мовчить — і модель ходить по колу

**Спіймано:** 22 серпня 2026, випробування `0002-shopping`, Mellum2-12B.
**Ціна:** усі 40 ходів, `{:too_many_turns, 40}`, жодного створеного файлу.

## Що видно в журналі

```
[каже]     return tool.list('.')
[програма]
[порожній хід]
[каже]     return tool.list('.')
[програма]
[порожній хід]
…і так сорок разів
```

Пісочниця цього випробування **порожня навмисне** — проєкт пишеться з нуля.
`tool.list('.')` чесно вертає порожню таблицю. Але модель бачить у відповідь
**нічого** — і не може відрізнити «тека порожня» від «виклик не спрацював».
Тому пробує знову.

## Де саме

`lib/keel_agent/session/program.ex:52`

```elixir
def said(values), do: Enum.map_join(values, "\n", &show/1)

defp show(pairs) when is_list(pairs) do
  if array?(pairs) do
    Enum.map_join(pairs, "\n", fn {_index, value} -> show(value) end)
```

`Enum.map_join([], "\n", …)` — це `""`. Порожня таблиця й відсутність
результату дають однаковий текст.

`array?([])` теж `true`, бо `Enum.all?` на порожньому переліку істинний, — тож
навіть гілка не та, але результат однаково порожній.

## Чому це вада, а не норма

Інструмент **збрехав мовчанням**. Він відпрацював успішно й повернув чесний
порожній результат, а модель прочитала це як «нічого не сталося». Різниця між
«є нуль речей» і «нічого не вийшло» — це те, за чим модель вирішує, що робити
далі, і ми її стерли.

Ціна названа: сорок ходів у нікуди.

## Лік

```elixir
# Порожній результат мусить читатись порожнім, а не зникати: модель, яка
# дістала нічого, не відрізнить успішного нуля від невдалого виклику й піде
# по колу. 22 серпня 2026 Mellum так спалила всі сорок ходів на порожній
# теці, жодного разу не спробувавши щось створити.
defp show([]), do: "(empty)"
```

## Ще одне, дрібніше

У тому ж журналі видно `[порожній хід]` поруч із кожним викликом. Тобто модель
не сказала **жодного слова** — самий код. Це не вада, але позначка в звіті
могла б казати ясніше: «модель нічого не сказала, тільки програма».


## Лік перевірено в бою

Повтор Mellum із ліком, той самий промт і ті самі ваги:

```
[каже]     return tool.list('.')
[програма] (empty)
[каже]     return tool.read("shopping_list.lua")
```

Замість сорока однакових ходів модель побачила `(empty)`, зрозуміла, що тека
порожня, і **одразу взялася до роботи** — читати й писати файли.

Тобто ті сорок ходів справді були нашою виною, а не її. Перший прогін Mellum
позначено недійсним:
`results/python/0002-shopping/mellum2-12b-6bit/20260822T202440-d27fec/NEDIYSNYY.md`.

**Що з цього НЕ випливає.** Що Mellum тепер упорається: плутанина мов у неї
лишилась — вона знову пише продукт на Lua з `tool.read` усередині. Лік прибрав
нашу перепону, а не її ваду.
