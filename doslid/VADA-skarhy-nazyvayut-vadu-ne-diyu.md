# Скарги називають ваду мовою розбору, а не мовою дії

27 серпня 2026. Третій випадок за вечір, тож це вже не збіг, а схема.

## Три випадки

### 1. `read` по теці — полагоджено

    було:  cannot read file (…): illegal operation on a directory
    стало: this is a directory, not a file — its listing is `list`

Laguna кільцювалась шість прогонів поспіль. Після правки послухалась першим
же викликом.

### 2. Заслон повторів — полагоджено

    було:  you already ran «list(".")» in this session
    стало: та сама відповідь, що й першого разу

Він блокував саме ту дію, до якої щойно направила перша правка.

### 3. `check` про YAML — **не полагоджено**

    header does not parse: line 6: a map inside a list is not supported:
    'parse/1 normalizes input: trims whitespace, converts comma decimal…'

Granite 8B написала в полі `meaning:` список прозових рядків. Кожен містить
двокрапку («parse/1 normalizes input**:** trims…»), і YAML читає це як мапу
всередині списку.

Скарга точна: named і рядок, і номер, і причину. Але не каже **дії** — узяти
рядок у лапки. Модель кілька ходів поспіль думає «треба перевірити формат
контракту», а шле `git commit`, який щойно відхилили.

## Пастка, яка нікуди не дінеться

Проза з двокрапкою в полі-списку — природний текст. Кожна модель, що
описуватиме поведінку словами, натрапить на це саме місце. Це не недбалість
однієї моделі, а властивість формату.

## Підтверджено двічі: та сама помилка в новому прогоні

Granite 8B, перезапущена начисто, написала контракт **дослівно так само**:

    meaning:
      - parse/1 normalizes input: trims whitespace, converts comma decimal…
    verify: [...] — tests must pass for all scenarios.

Та сама двокрапка в прозі, той самий хвіст після списку, та сама незакрита
шапка. Обидва рази — `✗ documents do not parse`.

Отже це не недбалість одного разу, а **стійка поведінка**: модель описує
поведінку прозою, бо так природно, і щоразу ламає YAML однаково. Першого разу
вона витратила десяток ходів, щоб самотужки додуматись до «прості пари в
шапці, проза в тіло».

Тобто ціна нечіткої скарги — не одна невдача, а десяток ходів **на кожному**
прогоні кожної моделі, що пише описи словами.

## Вимір на одній моделі, в одному прогоні

Другий прогін 8B дав чистий дослід: дві скарги поспіль про той самий файл,
різні за формою.

**Скарга, що веде до дії:**

    the header opens with --- on line 1 and never closes:
    add a line with nothing but --- after the last header field

→ модель виправила **з першого разу**.

**Скарга, що називає ваду мовою розбору:**

    header does not parse: line 6: a map inside a list is not supported

→ знову глухий кут. Думка каже «треба перевірити формат контракту,
перечитаю», а виклик іде `git commit` — той самий, що щойно відхилили.
Точнісінько як у першому прогоні.

Тобто різниця не в моделі, не в задачі й не в часі — **тільки в
формулюванні**. Одна скарга коштує одного ходу, друга — десятка.

## Як мало б бути

    line 6: a map inside a list is not supported. The text contains a colon,
    so YAML reads it as a key. Quote the whole line: - "parse/1 normalizes…"

Тобто: що не так → чому → **що зробити**, із прикладом на їхньому ж тексті.

## Правило, яке з цього випливає

Кожна відмова стенду має називати дію. «Не можна» без «а можна ось так» —
це коло, лише повільніше. Заслон, що каже правду мовою свого внутрішнього
розбору, для того, хто його читає, нічим не кращий за мовчання.

## Доповнення 27 серпня 2026: набір засобів різнився між режимами

У lua було дев'ять засобів, у python — вісім: бракувало `delete`. Qwen3.6
покликала його й дістала

    AttributeError: 'dict' object has no attribute 'delete' (line 5)

тобто мову внутрішнього пристрою замість слова про те, що засобу тут немає.
Три ходи вона будувала хибну гіпотезу — ніби сама затінила ім'я `tool`
власною змінною, — і шукала помилку там, де її не було.

Той самий рід вади, що й решта в цій нотатці: скарга каже, ЩО зламалось
усередині, а не ЩО робити. Але корінь глибший за формулювання — засобу
справді не було.

**Полагоджено:** `delete` доданий у python-міст; тест звіряє набори обох
режимів автоматично, тож розійтися вони більше не можуть мовчки.

**Правило, яке з цього випливає:** різниця між режимами — мова, а не те, що
моделі дозволено робити.
