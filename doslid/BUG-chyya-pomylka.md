# Повідомлення про помилку не каже, чиєї мови цей рядок

**Спіймано:** 23 серпня 2026, `0002-shopping`, Qwen3.6 — і раніше гемма.

## Що бачить модель

```
the program did not run: line 136: Expected expression
```

Це помилка **компілятора Lua**: наша віртуальна машина не змогла розібрати
програму моделі. Номер рядка — теж Lua-івський.

## Що думає модель

Qwen3.6, три ходи поспіль:

> The previous attempt failed because the file wasn't created due to the
> **syntax error in the Python code** (a stray bracket)

> The error `line 136: Expected expression` persists because the previous
> `tool.write` calls failed to create `shopping.py` due to **syntax errors in
> the Python code**

Вона шукає зайву дужку **в Python**, якого пише всередині Lua-рядка. А помилка
в самому Lua-рядку — найчастіше через екранування (див.
[BUG-podviyne-ekranuvannya.md](BUG-podviyne-ekranuvannya.md)).

Гемма 22 серпня зробила те саме: вісім ходів шукала ваду в Python, поки
причина сиділа в `\\n` усередині `[[...]]`.

## Чому це наша вада

Модель тримає **дві мови одночасно**: Lua, якою керує інструментами, і Python
(чи іншу), якою пише продукт. Повідомлення `line 136: Expected expression` не
називає жодної — і модель обирає ту, про яку думала останньої.

Це не дрібниця в словах. Обравши не ту, модель править не той файл, і кожна
спроба коштує повного ходу. У гемми це вісім ходів, у Qwen3.6 — три й далі.

## Лік

Сказати, чия мова й де:

```
the Lua program did not compile — line 136: Expected expression
(this is the Lua block you wrote, not the code inside it)
```

Другий рядок здається зайвим, але саме він знімає двозначність, на якій обидві
моделі спіткнулись.

**Не полагоджено.** Це зміна тексту, який бачить модель, — тобто норма.

## Заразом варте уваги

Обидві моделі, що спіткнулись тут, — це ті самі дві, що **єдині впорались** із
завданням. Тобто вада б'є не по слабких: сильна модель просто витрачає на неї
ходи, а слабка не доходить до неї взагалі.


## Доказ, у якому видно ціну двозначності

Qwen3.6, двадцять сьомий хід. Хвіст її програми:

```lua
]], "OK"))
```

**Дві закриті дужки замість однієї.** Виклик `tool.write(...` закритий двічі —
Lua не розбирає, і саме звідси «line 136: Expected expression» на останньому
рядку.

Модель у цей самий час пише:

> …due to syntax errors in the Python code (specifically, **a stray bracket**)

Тобто вона **правильно назвала рід помилки** — зайва дужка, — і хибно назвала
мову. Двадцять сім ходів шукала цю дужку в Python, де її немає.

Якби повідомлення казало «the Lua block you wrote», вона мала б шанс глянути
на рядок, який справді ламається.

## І ще: вона склеїла два свої минулі виправлення в нову ваду

`]], "OK"))` — це не лише зайва дужка. Це ще й **третій аргумент** до
`tool.write`, за який вона на початку прогону вже діставала:

```
tool.write() failed, expected 2 arguments, got 3
```

Тобто модель пам'ятає обидва свої минулі кроки, поєднує їх — і робить нову
помилку з двох старих виправлень. Це окремий різновид застрягання: не повтор,
а нашарування.
