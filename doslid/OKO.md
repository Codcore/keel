# Око над прогоном: три пастки, через які воно «мовчить»

**Знайдено:** 22 серпня 2026, під час прогонів Qwen3.8 і Ornith.

`mix agent.watch` працює справно. Мовчання щоразу мало іншу причину.

## 1. Око не чекає на сесію — треба повторювати спроби

**Спершу я записав тут протилежне.** Хибно: `mix agent.watch` не стоїть і не
чекає. Якщо вузла ще немає, він одразу виходить:

```
** (Mix) немає живої сесії на keel-agent@127.0.0.1 — її підіймає `mix agent.run`
```

А `mix` стартує кілька секунд. Тож ані «око першим», ані «око другим» саме
собою не рятує: у першому разі воно вискочить до початку прогону, у другому —
не встигне до кінця короткого. Так загубився цілий прогін Ornith на 50 секунд.

**Лік — повтор.** [tools/watch.sh](../tools/watch.sh) пробує щодві секунди,
поки не вчепиться:

```bash
tools/watch.sh &        # можна пускати до прогону
mix agent.run "..."
```

## 2. Сесія переживає хід і тримає ім'я вузла

Після `хід скінчився` сесія лишається живою — це задум, у ній можна
продовжити розмову через `remsh`. Але ім'я вузла `keel-agent@127.0.0.1` вона
теж тримає.

Наслідок: **наступний `mix agent.run` не стартує зовсім**.

```
** (Mix) вузол не піднявся: {:name_taken, :"keel-agent@127.0.0.1"}
```

А око при цьому чіпляється до **старої** сесії й чесно показує її тишу —
виглядає так, ніби зламане воно.

**Перед новим прогоном:**

```bash
pkill -f "mix agent.run"; sleep 3
epmd -names            # має лишитись тільки epmd
```

## 3. Після перезапуску машини немає epmd

Агент піднімає іменований вузол заради `remsh`, а той потребує демона
`epmd`, який після перезавантаження не стартує сам:

```
Protocol 'inet_tcp': register/listen error: econnrefused
** (Mix) вузол не піднявся: {:no_distribution, ...}
```

Лік — `epmd -daemon` один раз після перезапуску.

## Що з цього варте хвилі в самому агенті

- **`agent.run` міг би сам піднімати `epmd`** — зараз падає з повідомленням,
  зрозумілим лише тому, хто знає Erlang;
- **`agent.run` міг би сказати, хто саме тримає ім'я** — зараз `:name_taken`
  не називає ні pid, ні сесії, і оператор мусить сам іти в `epmd -names`;
- **потрібен спосіб спинити стару сесію** — зараз це `pkill` навмання.

Жодне з цього не зроблено: за домовленістю вада лагодиться відразу, а нова
норма — лише з дозволу. Це норми, тож вони тут чекають.

## 4. Три способи заглушити око власноруч

Усі три я зробив 22 серпня поспіль, і жоден не був виною інструментів.

**Підстановка команди.** `out=$(mix agent.watch | eye.py)` збирає весь вивід у
змінну й друкує наприкінці. Око мовчить увесь прогін, тоді вивалює все гуртом.
Треба прямий конвеєр.

**`cut` наприкінці.** `... | eye.py | grep ... | cut -c1-190` — `cut` буферизує
блоками, і рядки застрягають у ньому. `grep` рятує `--line-buffered`, `cut`
такого не має зовсім. Замість нього:

```bash
awk 'length($0)>2 { print substr($0,1,180); fflush() }'
```

**Око після прогону.** `mix agent.watch` показує лише те, що діється ПІСЛЯ
під'єднання, а `mix` стартує 5–8 секунд. Прогін Mellum тривав 8.4 с — наздогнати
неможливо. Для коротких прогонів єдине надійне джерело — лог від першого байта:

```bash
tail -f -c +1 "$LOG" | python3 -u eye.py
```

Саме це робить [tools/run.sh](../tools/run.sh): вмикає прогін і око однією дією.
