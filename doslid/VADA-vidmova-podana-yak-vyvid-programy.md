# Відмову подано моделі як вивід програми

**Знайдено:** 30 серпня 2026, у першому прогоні Nemotron Cascade 2 на 0006.

## Що коїться

`server.ex:1316` обгортає **будь-який** `said` заголовком:

```elixir
back(state, vyvid(said), turns - 1, used + 1, told(said))
defp vyvid(said), do: "Your program ran. It printed:\n\n" <> said
```

Модель бачить:

```
Your program ran. It printed:

running «find» is not allowed. Allowed: ./keel/keel, git, keel/keel, mix.
For that, use the «glob» tool instead.
```

Програма не виконувалась. Її заборонив заслон `command.ex:402`.

## Чому це наша вада, а не недогляд

Коментар над самим `vyvid` забороняє рівно це:

> Ставиться лише на вивід ПРОГРАМИ: відмови й нагадування — це справді голос
> середовища, і вдавати їх машинним виводом було б новою неправдою.

Намір записано правильно, код його не тримає: заслон вертає відмову тим самим
каналом, що й вивід, і `vyvid` не має як їх розрізнити.

## Другий прояв, гірший

Гілка `server.ex:1302`:

```elixir
{:error, {reason, _nothing}} -> "the program did not run: #{reason}"
```

після обгортки дає моделі буквальне самозаперечення:

```
Your program ran. It printed:

the program did not run: …
```

## Чого це коштує

За перший повтор Немотрона — 6 відмов на 78 викликів, з них 4 подано як
виконання. Модель учиться, що `find` і `grep` **працюють** і друкують помилку,
замість «цієї програми тут нема, бери засіб». Заголовок ставили саме щоб зняти
плутанину (гема 26B, 26 серпня, писала файл пʼять разів) — а на цьому шляху
він плутанину додає.

## Лік

`vyvid` має вішатись лише на справжній вивід. Відмова заслону й `did not run`
мусять іти без заголовка — вони голос середовища. Дивись
[[VADA-gemu-sorok-progoniv-godovano-dumkoyu-yaku-vona-ne-bachyla]]: там та сама
хвороба — годоване доїжджає не в тому вигляді, який ми думали.

**Правити після прогону:** sweep попереджає (рядки 14–15), що правка
компілюється в ту саму теку, з якої прогін бере код.

## Побічне: журнал двоїть кожен виклик — це НЕ роздуття контексту

У сесії кожна дія лежить двічі: раз ходом моделі з синтетичним id `call-N`
(`model.ex:150`), раз парою `tool_use`+`tool_result` від пісочниці зі справжнім
`call_xxxx`. Пишуть двоє, бо пісочниці дано `Turn.record` (`server.ex:1586`).

Блоки `call-N` не мають `tool_result` — тому при читанні логу здається, ніби
модель шле виклики, які нікуди не йдуть. Це неправда: контекст моделі будується
зі стану циклу, а не з журналу.

**Хто читає сесію очима — має рахувати виклики лише за `call_`-id**, інакше
кожне число вдвічі більше за справжнє.

## Куди саме потрапляє заголовок (перевірено)

`back/5` (`server.ex:1354`) кладе `Message.user(vyvid(said))` у `state.said` —
історію розмови. `openai_compatible.ex` перетворює таке повідомлення, що стоїть
**після** ходу з викликом, на роль `tool` із тим самим `tool_call_id`; це
доводить тест `openai_compatible_test.exs:538`.

Отже моделі йде **одна** копія, правильним каналом. Контекст не роздутий.
Але брехливий заголовок лежить у самому тілі відповіді на виклик.

`tool_result`-блоки з `chain.ex` пишуться лише в журнал — до моделі вони не
їдуть. Тому в журналі 82 результати й 82 `Your program ran`, а в контексті — 82.
