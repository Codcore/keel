# Вада: `[[ ]]` ламається об звичайний Python

**Коли:** 23 серпня 2026
**Де:** `agent/lib/keel_agent/sandbox/dialect.ex` — порада писати файл у `[[ ]]`
**Кого вбило:** GLM-4.7-Flash, гема — обидві на першому ж ході

## Що сталося

Ми радимо моделі класти вміст файлу в довгу дужку Lua:

> Inside `[[ ]]` nothing is escaped… To put a file on disk, write real line
> breaks inside the brackets.

GLM послухалась і написала Python:

```python
return [item for item in self.items if not item["bought"]]
```

Рядок 55. Lua побачив `]]` і закрив довгу дужку **на тридцять вісім рядків
раніше**, ніж модель її закрила. Далі почався розбір Python як Lua:

```
the program did not run: line 56: Expected :delimiter::rparen, got :keyword::if
```

Гема тим самим вечором упала так само, на своєму рядку 45.

## Чому це не крайній випадок

`]]` наприкінці рядка — це **список за умовою з підрядковим індексом**, одна з
найзвичайніших конструкцій Python. Так само ламаються `d[k[0]]`, `a[b[i]]`,
`m[x["y"]]`. Тобто наша порада не має рідкісного винятку — вона має **систематичну
діру рівно там, де модель пише робочий код**.

Двом моделям з двох, що послухались поради буквально, вона зіпсувала перший хід.

## Чого ми чекали від native tool calling — і чого не сталося

Оголошуючи `run_lua`, ми розраховували, що код поїде **полем JSON**, і
екранування зробить бібліотека замість моделі. Для GLM цього не сталось: вона
пише програму Lua й обгортає її своїми токенами `<tool_call>`, а не кладе в
аргумент. Тобто на довгу дужку ми лишаємось покладені й на новому шляху теж.

## Лік

Довгі дужки Lua мають рівні: `[==[ … ]==]` закривається тільки на `]==]`, і
`]]` усередині для нього просто два знаки. Це стандартна Lua, не наше
розширення.

Порада в діалекті переписана: рівень за домовленістю, а не за настроєм.
