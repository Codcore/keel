# `glob` ховає теки, і модель вирішує, що їх немає

**Знайдено** 30 серпня 2026, Лагуна на `0006-voda-work`, неквантований кеш.

## Ті самі дві теки, два засоби

```
list keel   ⇒ METHODOLOGY.md  PLAN.md  QUALITY.md  contracts/  keel
              keel.json  keel.py  waves/

glob keel/* ⇒ keel/METHODOLOGY.md  keel/PLAN.md  keel/QUALITY.md
              keel/keel  keel/keel.json
```

`contracts/` і `waves/` зникли. `keel.py` теж.

## Чого це коштувало

Модель подивилась через `glob`, побачила проєкт без тек — і пішла вгадувати
імена конфігу, якого немає:

```
keel.toml  ⇒ no file matches
keel.conf  ⇒ no file matches
keel.yml   ⇒ no file matches
keel.sh    ⇒ no file matches
```

Чотири порожні виклики з десяти. Плюс `lib/**/*` і `**/*.ex`, які теж нічого
не дали, бо `lib/` ще не було створено.

За 43 виклики вона зробила лише дев'ять команд і **жодного `keel check`** —
решта пішла на пошук того, що `list` показав би за один хід.

## Чому це наша вада

Засіб зветься «знайти за взірцем» і мовчки звужує світ до файлів. Модель не має
як дізнатися, що показане неповне: відмови немає, попередження немає, просто
коротший перелік. Це та сама хвороба, що й у
[[VADA-hovane-znykaye-z-perelikiv]]: заслон, який приховує, гірший за заслон,
який відмовляє, бо перший неможливо помітити.

## Лік

`glob` має показувати теки так само, як `list` — із скісною на кінці, щоб було
видно, що це тека, а не файл. Взірець `keel/*` мусить давати `keel/contracts/`
і `keel/waves/`.

**Правити після прогону:** `sweep.sh` компілює агента в ту саму теку, з якої
прогін бере код.
