# Режим `code-python`: зроблено й перевірено

**Коли:** 23 серпня 2026
**Перемикач:** `TOOLS=python` у `tools/sweep.sh`, `tools: :python` у конфігу

## Що це

Третій режим поруч із `code-lua` і `native`. Модель пише **програму на Python**,
яка кличе ті самі сім інструментів:

```python
import tool

tool.write("shopping.py", "print('hi')\n")
out = tool.run("pytest", ["-q"])
print(out)
```

Виконується в `Pyex` — інтерпретаторі Python на Elixir. Ті самі межі проєкту,
той самий ланцюг із заслоном і журналом: міст тонкий, робота лишається в
`KeelAgent.Tools`.

## Чим відрізняється від `code-lua`

**Не мовою, а тим, чого в промті немає.**

| режим | промт |
|---|---:|
| `code-lua` | 4087 байт |
| `code-python` | **3041 байт** |
| `native` | 1550 байт |

Тисяча байтів різниці — це дві сторінки діалекту: індекси з одиниці,
`table.create` не існує, склейка через `..`, рівні довгої дужки. Про Python не
треба нічого.

**І `return` не потрібен:** вертається значення останнього виразу, як у REPL.
`print` теж працює — надруковане приходить разом із результатом. У Lua
відсутність `return` коштувала нам окремої вади.

## Перевірено

**Пісочниця** — девʼять тестів: інструменти, відмова парою `None, reason`,
кодування в обидва боки, порядок аргументів, і чотири межі (`open`, `import os`,
нескінченний цикл, вихід за корінь).

**Промт** — просить Python, не згадує Lua жодного разу, коротший за луашний.

**Мітка блоку** — ```` ```lua ```` не читається в режимі Python і навпаки:
приймати обидві означало б виконати одну мову як іншу.

**Наживо** — гема: три ходи, 84 секунди, обидва файли, чотири зелені тести.

Разом 460 тестів зелені.

## Межа, названа наперед і побачена одразу

Модель кладе Python **усередину Python**:

```python
shopping_list_code = """
import json
...
"""
```

Тобто вкладення мови в мову нікуди не поділось — воно лише стало зручнішим, бо
потрійні лапки природніші за `[==[ ]==]`. Перевірено окремо: Pyex тягне потрійні
лапки з `with`, `def` і двокрапками всередині.

**Але для Elixir це зламається** так само, як Python ламався в Lua: у нього свої
`"""`. Для Python-проєктів режим природний; для чужих мов — ні.

## Прогін: пʼять заходів, і коли зупинитись

Кожен із перших чотирьох перезапусків знайшов справжню ваду:

1. промт казав, що в пісочниці немає нічого, крім `tool`;
2. забутий `import tool` губив хід;
3. модулі неповні — `os` є, `os.getcwd` немає, і з переліку це не видно;
4. `import` власного файлу не працює — перевіряти треба через `tool.run`.

Усі чотири полагоджені й записані окремо.

**Пʼятий захід уже нічого нового не дав.** Mellum і далі бере `subprocess`,
`os.path.abspath`, `contextlib.redirect_stdout` — і не створює файлів.

**Тут я зупинився з правками.** Не тому, що все ідеально, а тому, що це вже
**результат, а не вада**: режим `code-python` карає моделі, які спираються на
стандартну бібліотеку, і хвалить ті, що обходяться інструментами.

Правити далі означало б підганяти промт під одну модель — і зробити прогін
виміром власної впертості замість виміру моделей.

**Ознака, за якою я це впізнав:** нова правка перестала міняти **вид** помилок,
а міняла лише їхню кількість. Доти кожна відкривала інший шар.
